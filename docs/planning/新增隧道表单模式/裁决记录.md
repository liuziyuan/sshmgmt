## B3 表单校验规则 — 新增（2026-11-19，主控于阶段 1 校验时采纳）

1. **问题证据**：基线 B3 原文为「端口必须是 1–65535 的数字；主机地址、用户名、目标主机非空且不含空格；转发规则至少一条」。实现方案 §2.2/§3.4 在此之外新增三条禁令：转发目标主机禁含 `:`、跳板机地址禁含 `@`、私钥路径禁含双引号 `"`。依据为解析器实读行为：`parse_forward_spec` 按冒号切分，目标主机含 `:` 时四段错位且末段为数字时**静默"成功"**（parser.rs:150-188）；destination 按**最后一个 `@`** 切分，地址含 `@` 会被错拆（parser.rs:111）；shell-words 双引号剥除会使路径含 `"` 时包裹歧义。
2. **备选方案**：a) 仅按 B3 原文校验——含冒号目标主机会产生「看似保存成功、实际转发到错误地址」的隧道，违反 B2 往返一致与 B3「不产生非法命令」的意图；b) 扩展解析器支持 IPv6 目标/转义——违反基线「后端零改动」硬约束，直接否决；c) 三条禁令 + 中文说明文案（方案采纳项）。
3. **裁决**：采纳 c)。校验不通过 = 字段红字 + 保存禁用，UI 文案明确说明「暂不支持含冒号的地址（如裸 IPv6）」。
4. **理由**：基线第 6 节已预留授权（「解析器对转发目标主机含 `:` 的支持情况以 parser.rs 实际行为为准」设计 B2/B3 校验）；三条禁令各对应一条已核实的解析器行为，是 B3 目的的必要条件，属细化而非范围扩张。
5. **影响**：B3 可接受输入集合比基线文字更窄（只收紧不放松），无验收标准被放松。遗留假设：转发目标主机为 IPv6 字面量的场景极少，不支持不影响主路径；若用户要求支持，需推翻「后端零改动」约束（打断边界第 2 类，届时上报）。跳板机 IPv6 不受影响（表单填裸地址、拼装自动包 `[]`，往返无损）。

## B3 红字字段定位的校验返回类型 — 偏离（2026-11-19，主控于阶段 1.5 校验时采纳）

1. **问题证据**：实现方案 §2.2 写「校验实现为纯函数 `validateFormState(s): string[]`」，但同节同时要求「违规字段下方红字提示」——纯消息列表无法做字段级定位，两处要求矛盾；实施计划将返回类型细化为 `FormFieldError { field, message }[]`（实施计划 §2、§3 步骤 1）。
2. **备选方案**：a) 维持 `string[]`，红字只在表单顶部整体展示——字段级红字要求落空，与方案文案设计冲突；b) 按细化的 `{field, message}[]`——满足字段级红字定位，其 message 集合语义与 `string[]` 兼容。
3. **裁决**：采纳 b)。
4. **理由**：矛盾出在方案内部而非基线；字段级定位是「红字提示」的必要实现形态，校验规则本身（哪些输入非法）零变动，B3 语义不变。
5. **影响**：仅函数签名层面的实现细化；基线 B1–B8 无变动。评审与后续维护以 `FormFieldError` 形态核对该函数。

## S1 shell-words 特殊字符（`'` `"` `\`）漏禁 — 改写（2026-11-19，主控采纳评审报告，取代第 1 条中「`'` 无需禁」推断）

1. **问题证据**：评审报告 §1-S1（证据：parser.rs:16 `shell_words::split` 按 POSIX 规则分词；tunnelEditorForm.ts:72-89/106-122/131-133 校验仅查空格/@/:/`"`）。对抗推演证实：identityFile=`C:\Users\me\.ssh\id_ed25519`（Windows 高频形态，无空格）拼装后 `\U`→`U` 等转义致 identity_file=`C:Usersme.sshid_ed25519`，**静默错位、保存成功**；`'` 未闭合致后端解析报错。实现方案 §2.2「`$`/`'` 无需禁」断言自我矛盾（剥引号恰恰意味着引号参与配对），被证据推翻。
2. **备选方案**：a) 自动引号包裹替代禁令——`\` 在双引号内的行为依赖 crate 实现细节，不稳；b) 四字段统一禁 `'`/`"`/`\` 三字符（评审修法）——数行校验，确定性最强。
3. **裁决**：采纳 b)，打回实现 agent 修复。jumpUser/jumpHost/remoteHost/identityFile 统一禁三字符，中文红字提示。
4. **理由**：S1 为静默错位（比报错更危险），Windows 私钥路径是高频真实输入，违反 B2「逐字段相等」与 B3「不产生非法命令」；修复成本极低且不动架构。
5. **影响**：取代第 1 条裁决中对方案 §2.2「`'`/`$` 无需禁」的采纳（`$`/`` ` ``/`~` 经评审推演确认无损、仍不禁）；B3 禁令集合扩为：空格、`:`、`@`、`"`、`'`、`\`（按字段适用）。B2/B3 由「不满足/不完全满足」转为修复后待复核。
