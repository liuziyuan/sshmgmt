## 1. 问题清单（按严重度排序）

### 严重

#### S1：校验未拦截 shell-words 特殊字符（`'`、`"`、`\`），四个自由文本字段可拼出「后端解析报错」或「静默错位」的命令

**证据**：

- `src-tauri/src/parser.rs:16`：`let tokens = shell_words::split(raw)?;` —— 整条命令按 POSIX shell 规则分词（非引号上下文 `\x` 转义为 `x`；未闭合引号报 `Err`；成对引号剥除）。实现方案 §0 F5 自证：*"shell_words::split 分词（POSIX 风格，支持单/双引号与转义）"*。
- `src/components/tunnelEditorForm.ts:72-89`：jumpUser 仅查非空/空格；jumpHost 仅查非空/空格/`@`。
- `src/components/tunnelEditorForm.ts:106-122`：remoteHost 仅查非空/空格/`:`。
- `src/components/tunnelEditorForm.ts:131-133`：identityFile 仅查 `"`，**未禁 `'` 与 `\`**。
- 实现方案.md §2.2：*"…`$`/`'` 无需禁（shell-words 只做分词剥引号，不做变量展开）"* —— 该断言自我矛盾：**「只做剥引号」恰恰意味着 `'` 会参与引号配对与剥除、`\` 会做转义**。

**对抗推演形态**（表单值 → 拼装命令 → shell_words 分词结果）：

| # | 表单字段值 | 拼装命令片段 | 解析结果 | 性质 |
|---|---|---|---|---|
| 1 | identityFile=`C:\Users\me\.ssh\id_ed25519`（无空格，Windows 常见形态） | `-i C:\Users\me\.ssh\id_ed25519` | `\U`→U、`\m`→m、`\.`→.、`\i`→i → identity_file=`C:Usersme.sshid_ed25519` | **静默错位，保存成功** |
| 2 | identityFile=`a'b'c` | `-i a'b'c` | 引号配对剥除 → `abc` | **静默错位，保存成功** |
| 3 | identityFile=`a'b` | `-i a'b` | 未闭合引号 → shell_words `Err` | 保存报错（有后端兜底，但违反 B3） |
| 4 | jumpUser=`u"s"er` | destination=`u"s"er@host` | token=`user@host` → user 静默错位 | **静默错位，保存成功** |
| 5 | remoteHost=`a'b'` | `-L 8080:a'b':3306` | token=`8080:a:3306` → remote_host=`a`，"看似成功" | **静默错位，保存成功** |
| 6 | jumpHost=`ho'st` | destination=`u@ho'st` | 未闭合引号 → `Err` | 保存报错 |

**后果**：形态 1/2/4/5 为**静默错位**——校验放行、保存成功、配置错乱，用户完全无感知（形态 1 对本应用 Windows 用户是高频真实形态：私钥路径几乎必然含 `\`，保存后连接时私钥找不到 → 认证失败红灯且无从知道原因）。形态 3/6 有 `add_tunnel` 内部 `parse_ssh_command` 兜底报错（`commands.rs:48` → `saveError` + `notify("error")`），但违反 B3「不产生非法命令」，且报错是解析器英文原文。

**建议修法**：`validateFormState` 对 jumpUser/jumpHost/remoteHost/identityFile 四字段统一禁 `'`、`"`、`\`（identityFile 已禁 `"`，补 `'` 与 `\` 即可），红字文案如「不能包含引号或反斜杠字符」。不建议用「自动引号包裹」替代：`\` 在双引号内的保留行为依赖 crate 实现（POSIX 双引号内 `\` 仅在 `` $ ` `` `"` `\` 前转义），直接禁最稳。

### 一般

#### G1：jumpHost 畸形方括号可绕过 normalize，静默入库垃圾地址

**证据**：`src/components/TunnelEditor.tsx:251` onChange 只过 `stripHostBrackets`；`tunnelEditorForm.ts:48-53` 仅剥**成对** `[...]`；validate 对 jumpHost 只查空格/`@`。

**推演**：jumpHost=`[::1]x`（不成对）→ strip 不动 → validate 通过 → 拼装因含 `:` 包括号成 `u@[[::1]x]` → `parser.rs:192-204` `find(']')` 取**第一个** `]` → host=`[::1` ≠ 表单原值 `[::1]x`，静默入库畸形地址。历史命令侧同理：`ssh ... u@[::1`（漏右括号）解析为 host=`[:`，回填后不被拦截，垃圾持续往返。

**后果**：保存成功、连接时报错（用户看到红灯但难定位原因）。畸形输入形态，概率低，故列一般级。

**建议修法**：jumpHost 校验禁 `[`/`]`（onChange 已自动剥合法成对括号，剩余带括号输入均为畸形）；`configToFormState` 回填时对 jumpHost 同样过 `stripHostBrackets`。

#### G2：命令→表单异步回填与用户编辑竞态，用户已输入内容可被静默丢弃

**证据**：`src/components/TunnelEditor.tsx:106-131`——`setActiveTab(tab)` 即时切 Tab 后发起 `parseCommand(rawCommand)`；`:116-117` 成功回调仅做 seq 检查后 `setFormState(configToFormState(cfg))` 全量覆盖。seq 令牌只防「多次切换」的过期响应，**不防同一逻辑切换期间用户已编辑表单**。

**推演**：切到表单 Tab → IPC 往返期间（后端忙时可达数百 ms）用户在用户名/端口输入 → 响应返回 seq 匹配 → 全量覆盖 → 用户输入丢失、无提示。

**后果**：低概率（IPC 通常快）但真实存在；输入静默丢失。方案 §5.1 竞态设计只覆盖切换间竞态，实现忠于方案，属方案层缺口。

**建议修法**：回填前对 formState 做 dirty check（与 mount 初始快照比对），已脏则放弃回填并 notify 提示；或回填后追加提示「表单已按命令刷新」。

#### G3：identityFile 校验红字位于折叠区内，收起时保存按钮禁用但无可见原因

**证据**：`src/components/TunnelEditor.tsx:313` `{advancedOpen && (...)}` 条件渲染；`:333` identityFile 红字在折叠区内；`:420-425` 保存按钮禁用条件覆盖该错误但折叠收起时全表单无任何红字。

**推演**：存量 identity_file 含特殊字符可真实存在（历史命令 `-i a\"b` 经 shell_words 转义保留 `"`）→ 编辑回填 → 红字不可见 → 按钮灰、原因不可见。

**后果**：可恢复（展开即见），排查体验差；触发概率低。

**建议修法**：折叠条显示错误角标（如「高级选项（有 1 项错误）」），或折叠收起时表单底部汇总一条错误。

### 建议

#### P1：B1 判定口径存在歧义——表单保存会把 raw_command 改写为规范化拼装命令

**证据**：需求基线 B1「最终 TunnelConfig 完全一致（除自动生成的 id/name 外）」，而 `TunnelConfig` 含 `raw_command`（`src/types.ts:10`）；表单新增走 `addTunnel(cmd,...)`（`TunnelEditor.tsx:190`），cmd 为规范化命令（如 `ssh -g -L …`，不拼 `-f/-N`），与人工验收 V6-① 的对照命令 `ssh -fNg -L …` **字节不同但语义字段逐行一致**。

**说明**：若「等价命令」取规范化形态（粘贴表单拼出的同一条命令），raw_command 逐字节一致，B1 严格成立；raw_command 的形态差异无功能后果（仅编辑回填 textarea 时展示）。建议在验收口径中明确「语义字段一致 + raw_command 以规范化命令为对照」，消除歧义。不构成阻断。

#### P2：方案 §5.1「命令 Tab 已有的 parseError 红字继续可见」与条件渲染实现不符

**证据**：实现方案.md §5.1 原文如引；`TunnelEditor.tsx:340` `{activeTab === "command" && (...)}` —— 切到表单 Tab 后 command 块整体卸载，parseError 红字不可见（状态保留，切回命令 Tab 后重现）。

**说明**：warn notify 常驻提示已覆盖失败告知职责，实质无缺陷；属方案措辞偏差，建议后续修订方案措辞。不构成阻断。

#### P3：端口字符串规范化差异（"022" → 22）

**证据**：`tunnelEditorForm.ts:56-61` `/^\d+$/` 放行 "022"（数值 22）；`formToCommand:157` `Number(jumpPort) !== 22` → 不拼 `-p` → 解析回 22 → 回填 "22" ≠ "022"。

**说明**：数值语义无损（22==22），首尾零属显示规范化，极端形态，不影响验收。追求逐字符串严格相等可在 onChange 规范化。

#### P4：转发行 `key={i}` 用数组索引作 React key

**证据**：`TunnelEditor.tsx:268`。受控组件按 value 渲染无值错乱，仅删除中间行时输入焦点可能跳行；现有 preview 同款（现状一致）。可忽略。
