# 需求基线：新增隧道表单模式

> 冻结时间：2026-11-19
> 冻结方式：用户在讨论阶段对提案逐节明确确认（「OK 同意」），并以本主题激活 /pipeline，视为按已确认内容冻结。
> 来源：主工作区 `docs/planning/提案-新增隧道表单模式.md`（未提交、不在 worktree 基线内；本文为其完整镜像与冻结版，实施以本文为准）

## 1. 目标

让不了解 SSH 端口转发概念的新人也能通过表单创建隧道；同时完整保留现有「粘贴 ssh 命令」模式，老用户零迁移成本。

## 2. 非目标（硬边界）

- 不支持 `-J`（ProxyJump）、`-D`、`-R`——与 `parser.rs` 现状对齐，表单不提供这些入口。
- 不做隧道模板、连接向导等更重的引导。
- 不改后端数据模型与接口（`src-tauri/**` 不动）。

## 3. 约束

- **后端零改动**：`src-tauri/**`、`src/types.ts` 均不得修改。
- 改动集中在前端 `src/components/TunnelEditor.tsx`（可新增同级组件文件）。
- UI 文案全部中文，代码注释英文（仓库约定）。
- 新增可失败操作需接入 App.tsx 的 notify 机制（现有保存失败已接入，保持）。

## 4. 验收标准（B1–B8）

| # | 标准 |
|---|---|
| B1 | **配置等价**：表单模式创建的隧道，与粘贴等价命令创建的隧道，最终 `TunnelConfig` 完全一致（除自动生成的 id/name 外）。 |
| B2 | **往返一致**：表单值 → 拼装命令 → `parseCommand` 解析回的结构化字段，与表单输入逐字段相等（含多条转发、`-g`、`-i`、自定义端口）。 |
| B3 | **表单校验**：端口必须是 1–65535 的数字；主机地址、用户名、目标主机非空且不含空格；转发规则至少一条。不合法时保存按钮禁用或提示，不产生非法命令。 |
| B4 | **编辑回填**：粘贴命令创建的旧隧道，编辑时表单各字段（含高级选项）正确回填，保存后不丢配置。 |
| B5 | **Tab 双向转换**：两个方向切换都不丢数据；转换失败（如命令解析报错）时给出明确提示且不覆盖另一侧已有内容。 |
| B6 | **默认 Tab**：首次打开默认表单；之后记住用户上次的选择（本地偏好存储）。 |
| B7 | **兼容性**：粘贴命令模式行为与现状完全一致；后端无任何接口/模型变更。 |
| B8 | UI 文案全部中文，符合仓库既有约定。 |

## 5. 已定决策（用户已确认，实施不得推翻）

| # | 决策 | 结论 | 理由 |
|---|---|---|---|
| D1 | 默认 Tab | 默认表单 + 本地记住上次选择 | 新人首次必须落在表单；老用户切一次后直接停在命令 Tab。 |
| D2 | 高级选项折叠区内容 | `-g`（监听所有网卡）+ 私钥文件路径 | 后端已支持但新人少用；折叠既不丢能力又不吓退新人。`auto_reconnect` 不进表单。 |
| D3 | 数据链路 | 前端拼命令，复用现有 `parse` 链路，后端零改动 | 编辑/导入导出/持久化都以 `raw_command` 为源头；新开结构化接口成本高、无用户可见收益。 |
| D4 | 编辑回填来源 | 直接用结构化字段，不反解命令 | 结构化字段就在 config 里，反解引入额外失真面。 |
| D5 | Tab 切换互相同步 | 是，双向自动转换 | 命令 Tab 始终可见等效命令，对新人有教学价值。 |

## 6. 已知边界（记录在案，不随本需求解决）

- 粘贴命令里若带四段式 `-L`（`bind:lport:rhost:rport`），现有解析会丢弃绑定地址——既有行为，表单编辑后保存不会更差。
- 解析器对转发目标主机含 `:` 的支持情况以 `parser.rs` 实际行为为准，方案设计前必须先读解析器核实（涉及 B2/B3 的校验规则设计）。
