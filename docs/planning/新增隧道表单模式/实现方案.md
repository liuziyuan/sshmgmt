## 1. Tab 双模式交互设计（B6，D1）

### 1.1 布局

弹窗标题下新增一条 Tab 切换条（两个按钮的 segmented control）：

```
编辑隧道 / 新增隧道
[ 表单填写 ] [ 粘贴命令 ]      ← Tab 切换条
（Tab 内容区：表单 或 命令 textarea + 解析预览）
显示名称 / 项目分组 / 环境      ← 公共字段，移到 Tab 内容区之下（原顺序不变）
saveError / 按钮（取消、保存）
```

- name/group/environment 是两个模式共有的元数据字段，**移出 Tab 内容区**作为公共区，避免 Tab 转换时互相覆盖；顺序与现状一致（在转发内容之后、按钮之前）。
- Tab 内容区按 `activeTab` 二选一渲染：`"form"` 渲染表单；`"command"` 渲染现有 textarea + parseError + preview（UI 与现状完全一致）。

### 1.2 默认 Tab 与记忆（B6，D1）

- 存储：`localStorage`，key = `sshmgmt.editor.tab`，value = `"form" | "command"`。
- 读：在 `activeTab` 的 useState 初始化器中执行（F1 条件挂载保证每次打开恰好读一次）。解析逻辑：读到 `"command"` → 用 command；其余一切情况（key 不存在、值非法、localStorage 抛异常）→ 默认 `"form"`。读写均包 try/catch。
- 写：用户每次切换 Tab 成功后写入目标 Tab 值；写入失败（异常）静默降级——本次会话内 Tab 状态不受影响，仅下次打开不记忆。
- 容错降级的兜底永远是默认表单（D1：新人首次必须落在表单）。

### 1.3 编辑打开时的 Tab（D1+D4 组合）

编辑打开同样按 1.2 的记忆值决定初始 Tab。表单侧内容由 §4 的结构化回填在 mount 时一次性就绪，因此无论落在哪个 Tab，两侧内容都已一致，用户切换无需等待解析。

## 2. 表单字段清单与校验规则（B3）

### 2.1 字段清单（FormState）

新增纯函数文件 `src/components/tunnelEditorForm.ts`（无 React 依赖，见 §8）定义：

```ts
interface ForwardRow { localPort: string; remoteHost: string; remotePort: string }
interface EditorFormState {
  jumpUser: string;     // 跳板机用户名
  jumpHost: string;     // 跳板机地址（裸地址；IPv6 不带方括号）
  jumpPort: string;     // 跳板机端口（input 绑定 string，校验时转数字；默认 "22"）
  forwards: ForwardRow[];
  bindAll: boolean;     // -g
  identityFile: string; // 私钥路径，空 = 不使用
}
```

端口以 string 承载（避免输入中间态产生 NaN）；`configToFormState` 回填时 `String()` 转换。

### 2.2 校验规则（B3 + 基线第 6 节授权）

基线第 6 节明确"解析器对转发目标主机含 `:` 的支持情况以 parser.rs 实际行为为准"（F10 已核实：无法往返且可能静默错位），故在 B3 的"非空、不含空格"之外补充以下禁令，均有 F10/F9 推演背书：

| 字段 | 规则 | 依据 |
|------|------|------|
| 跳板机用户名 | 非空；不含空格 | B3 原文；含空格会被 shell-words 拆成两个 destination token（F11 错乱） |
| 跳板机地址 | 非空；不含空格；**不含 `@`** | B3 原文；含 `@` 时 `user@host@host2` 会被 rfind('@') 错拆（F8）——host 变成 `@` 之后内容 |
| 跳板机端口 | 整数 1–65535 | B3 原文；65536+ 与 0/负数均拦截（u16 parse 虽接受 "0"，语义非法） |
| 转发本地端口 | 整数 1–65535 | B3 原文 |
| 转发目标主机 | 非空；不含空格；**不含 `:`** | B3 原文 + F10：含 `:` 时 4 段错位（`-L 8080:a:b:3306` → rhost=`a`、rport=3306"看似成功"的静默错位）或 5+ 段报错，均无法往返。UI 文案说明"暂不支持含冒号的地址（如裸 IPv6）" |
| 转发目标端口 | 整数 1–65535 | B3 原文 |
| 转发规则数量 | ≥ 1 条 | B3 原文（F12：`forwards.is_empty()` 时解析直接 bail，空表单不可能产生合法命令） |
| 私钥路径 | 可空；不含 `"`（双引号） | 含空格**允许**（拼装时自动双引号包裹，见 §3 规则 4）；`"` 会破坏包裹歧义故禁止；`$`/`'` 无需禁（shell-words 只做分词剥引号，不做变量展开）。~~`'` 无需禁~~ **修订（2026-11-19，评审 S1 与裁决记录第 3 条）**：`'`/`"`/`\` 三字符已统一禁（jumpUser/jumpHost/remoteHost/identityFile 四字段）——`'` 参与引号配对剥除、`\` 参与 POSIX 转义，两者均可造成静默错位（如 Windows 路径 `C:\Users\...`），原断言被评审对抗推演推翻；`$`/`` ` ``/`~` 经推演确认无损，仍不禁。另 jumpHost 增禁 `[`/`]`（畸形括号，评审 G1） |
| 跳板机地址含 `:` | **允许**（即 IPv6），表单要求输入裸地址，拼装自动包 `[]` | F9：不加 `[]` 会静默错拆；加 `[]` 往返无损。字段说明文案："IPv6 地址直接填写即可（如 ::1），无需方括号" |

- 校验实现为纯函数 `validateFormState(s): string[]`（返回错误消息列表，空数组 = 合法），表单 Tab 下每次 formState 变更后派生重算。
- 不合法时的表现（B3"保存按钮禁用**或**提示"，两者都做）：违规字段下方红字提示 + 保存按钮禁用。**不产生非法命令**的另一重保险：`formToCommand` 只在校验通过后调用（返回 result 类型，见 §3），两处调用点（切 Tab、保存）都先校验。

### 2.3 字段中文文案要点（B8）

- 跳板机地址：说明文案须包含**「目标主机是从跳板机看过去的地址」**这一要点（如占位符示例 `-L 10008:目标主机:3306` 的旁边提示："转发目标主机 = 从跳板机看过去的地址，例如内网 IP 或内网域名"）。
- 其余文案见 §9 文案清单。

## 3. formToCommand 拼装规则与往返推演（B1、B2，D3）

### 3.1 拼装模板

```
ssh [-g] [-p PORT] [-i PATH] -L SPEC1 [-L SPEC2 ...] USER@HOST
```

固定顺序：`ssh` 前缀 → `-g` → `-p` → `-i` → 逐条 `-L` → destination 最后（F11：destination 后再无非 flag token，不会被覆盖）。跳板机端口不拼在 `host:port` 形式上，统一走 `-p`（显式、避免与 IPv6 括号叠加歧义）。

`formToCommand(s): { ok: true; command: string } | { ok: false; errors: string[] }`——内部先跑 `validateFormState`，非法即返回 errors，不产出半残命令。

### 3.2 逐条拼装规则与往返推演

每条格式：**表单值 → 拼出的命令片段 → parseCommand 解析回的值**（依据 = parser.rs 行号见 §0 表）。

1. **`ssh` 前缀**：恒拼 `ssh`。→ 解析器跳过该 token（F5）。表单值不涉及；不拼也合法，拼上更符合用户对命令 Tab 教学价值的预期（D5）。

2. **`-g`**：`bindAll=true` → 拼独立 token `-g`；false → 不拼。→ 无参 flag 逐字符分支，`bind_all=true`（F7）。往返：true→true、false→false ✅。不学 `-fNg` 组合式（`-f/-N` 会被忽略，拼了只会误导读者）。

3. **`-p`**：`jumpPort` 数值化后 ≠ 22 → 拼 `-p {port}`；= 22 → 不拼。→ FLAGS_WITH_ARG `'p'`，arg parse u16 存入 jump_port（F6）。往返：22（默认，F12 初值 22）→ 22 ✅；2222 → 2222 ✅。B3 已保证 1–65535，不会产出 u16 溢出值。

4. **`-i` 与路径含空格的引号规则**：`identityFile` 非空 → 拼 `-i` + 空格 + 路径；路径含空格 → 双引号包裹 `-i "/path/with space/key"`；不含空格 → 裸拼。→ FLAGS_WITH_ARG `'i'`，分离式取下一 token，shell-words 剥双引号后得到完整路径存入 identity_file（F5、F6）。往返：`"/Users/a b/id_ed25519"` → `/Users/a b/id_ed25519` ✅ 逐字符相等。路径含 `"` 已被 B3 校验拦截（§2.2）。**不用 `-i=path` 形式**：紧凑式会把 `=` 并进 arg（`identity_file="=path"`，F6 的 rest_of_tok 机制），故必须空格分离式。**值以 `-` 开头也安全**：F6 核实下一 token 作为 arg 时不检查 `-` 前缀。

5. **`-L` 转发规则**：每条 `{localPort, remoteHost, remotePort}` → 拼 `-L` + 空格 + `{localPort}:{remoteHost}:{remotePort}`（分离式）。→ FLAGS_WITH_ARG `'L'` 取下一 token，`splitn(4,':')` 恰 3 段（B3 已禁 remoteHost 含 `:` 与空格），`local_port/remote_port` parse u16 成功（B3 已保证范围），`remote_host` 原样 ✅。多条转发按数组顺序逐条拼接，解析循环按 token 顺序 push，**顺序保持** ✅（B2"含多条转发"）。

6. **destination 与用户名含 `@`**：`{jumpUser}@{jumpHost}`。→ `rfind('@')` 按**最后一个 `@`** 分割（F8）。推演：用户名 `liu.zy@pg.com` + 主机 `10.125.24.20` → `liu.zy@pg.com@10.125.24.20` → user=`liu.zy@pg.com`、hostport=`10.125.24.20` ✅ 逐字段相等。用户名不含 `@` 时同理。用户名含空格已被 B3 拦截（否则 shell-words 拆裂 destination，F11）。

7. **跳板机 IPv6 加 `[]` 规则**：`jumpHost` 含 `:` → destination 拼 `{jumpUser}@[{jumpHost}]`；不含 → 原样。→ parse_hostport 以 `[` 开头走 IPv6 分支，**剥掉方括号**返回裸 host（F9）。往返：表单 `::1` → 命令 `deploy@[::1]` → 解析回 host=`::1` ✅。**反证（为何必须加）**：裸拼 `deploy@::1` → hostport=`::1` → rfind(':') 末段 `1` 是合法 u16 → host=`:`、port=1，**静默错位**（F9）。因此"含 `:` 即包 `[]`"是硬规则；B3 不禁 jumpHost 含 `:` 正是为此，两端（表单要求填裸地址、拼装自动加括号）配合闭环。用户若手输 `[::1]`，`configToFormState`/输入 normalize 时剥掉首尾方括号再存裸地址（宽容处理）。

8. **name/group/environment**：不进命令。解析产物里 `name` 缺省自动生成、`group/environment` 为 None（F12），由保存链路入参覆盖（§6）。表单 Tab 下 name 留空 → `addTunnel(cmd, undefined, ...)` → 后端自动生成，与命令模式留空行为一致 ✅。

### 3.3 B1（配置等价）的成立路径

表单创建与粘贴等价命令创建，最终都经过同一个 `parse_ssh_command`（F13：add_tunnel 内部即解析）。若两条命令字节一致，产物 config 必然一致（同一纯函数）。§3.2 各规则证明"表单值 → 命令"的拼装结果与手工书写等价命令的解析产物逐字段一致（除 id 恒为新 UUID、name 同规则生成外）。故 **B1 归结为 B2 的往返一致 + 同一解析器**，作证手段见 §13。

### 3.4 无法往返、必须禁掉的形态（B3 校验依据汇总）

| 表单输入形态 | 若不禁会发生什么 | 结论 |
|---|---|---|
| 目标主机含 `:` | 4 段错位（rhost 取中段，末段为数字时静默"成功"）或报错（F10） | 禁，红字提示 |
| 目标主机/跳板机地址/用户名含空格 | shell-words 拆裂 token：`-L` arg 残缺报错、destination 错乱（F5、F11） | 禁（B3 原文） |
| 跳板机地址含 `@` | rfind('@') 错拆，`@` 后内容被当 hostport（F8） | 禁 |
| 私钥路径含 `"` | 双引号包裹歧义，剥引号后路径残缺 | 禁 |
| 端口 ∉ [1,65535] | u16 溢出报错或 0 端口语义非法 | 禁（B3 原文） |

## 4. 编辑模式结构化回填（B4，D4）

- **回填来源**：`editTarget.config` 的结构化字段，**不反解命令**（D4）。实现为纯函数 `configToFormState(cfg: TunnelConfig): EditorFormState`：
  - `jump_user → jumpUser`、`jump_host → jumpHost`（原样裸地址；IPv6 存量数据本就是剥括号形态，见下）、`String(jump_port) → jumpPort`；
  - `forwards` 逐条深拷贝重命名：`{ String(local_port), remote_host, String(remote_port) }`（不引用 config 对象，避免编辑直接污染原 config）；
  - `bind_all → bindAll`；`identity_file ?? "" → identityFile`。
- **mount 时机一次性回填**（F1 条件挂载）：编辑打开时 `rawCommand` 初值仍为 `editTarget.config.raw_command`（现状不动），同时 `formState` 初值 = `configToFormState(editTarget.config)`。两 Tab 内容即同一 config 的两种视图，天然一致。
- **IPv6 存量回填闭环**：历史 config 的 `jump_host` 若为 IPv6，只可能是当初命令写了 `[::1]` 被剥括号后的裸地址 `::1`（F9 裸 IPv6 根本解析不进来）。回填 `::1` → 拼装再包 `[]` → 解析还原 `::1` ✅ 往返无损。
- **含 `:`/`@` 的存量字段**：能存进 config 的 `remote_host` 必然不含 `:`（F10 冒号切分），`jump_host` 必然不含 `@`（F8 拆分），故回填后校验不会因历史数据意外卡死。`jump_user` 允许为空字符串（历史命令可缺用户名，F8），回填后触发 B3"用户名非空"红字，用户补填即可，属预期行为。
- **高级选项回填**：`bind_all`、`identity_file` 在折叠区内正确回填（折叠只是视觉收起，值已就绪），B4"含高级选项"覆盖。
- **保存不丢配置**：表单 Tab 保存走 formToCommand → 解析链路（§6），`auto_reconnect` 由解析器固定为 true（F12，存量亦然，无差异）；group/environment 经入参显式回传；四段式 `-L` 的 bind 本就已被解析器丢弃（基线已知边界，表单保存不会更差）。

## 5. Tab 双向转换方案与失败处理（B5，D5）

### 5.1 命令 Tab → 表单 Tab

- 触发：点击"表单填写"。
- 流程：`activeTab` 先切为 form（Tab 即时响应）；若 `rawCommand.trim()` 为空 → 不解析，表单保持现有值（空命令不算失败）；否则发起 `parseCommand(rawCommand)`（异步 IPC），成功 → `setFormState(configToFormState(cfg))`（**只覆盖转发语义字段，不碰公共字段** name/group/environment，见 §1.1）；失败 → `notify("warn", "命令解析失败，表单保持原有内容：...")` + 命令 Tab 已有的 parseError 红字继续可见。两种结果都写入 localStorage `"form"`（Tab 切换本身已完成）。
- **不覆盖语义**（B5"转换失败不覆盖另一侧"）：parse 失败时 formState 分文不动；parse 成功才覆盖表单侧转发字段。
- 竞态防护：模块内 `switchSeqRef`（useRef 计数器），发起解析前 `++seq` 捕获快照，响应返回时 `seq` 不一致则丢弃（用户快速来回切换时过期响应不得回填）。
- **命令→表单→命令会重写命令文本**（如 `-fNg` → `-g`、紧凑 `-L10008:...` → 分离式）：这是 D5"双向自动转换"的必然结果，语义等价、解析产物逐字段一致；保存以当前 Tab 为源（§6），链路以 raw_command 为源头（D3），基线已接受该形态。

### 5.2 表单 Tab → 命令 Tab

- 触发：点击"粘贴命令"。
- 流程：`activeTab` 切为 command；`formToCommand(formState)`（本地同步纯函数，无 IPC、无竞态）：合法 → `setRawCommand(command)`，现有防抖 useEffect（§1.1 已加 gate）随即解析并刷新 preview；非法 → `notify("warn", "表单信息不完整，已保留原命令内容")` + 表单侧红字保持，rawCommand **分文不动**。两种结果都写 localStorage `"command"`。
- 切 Tab 允许在校验未过时进行（切换 ≠ 提交），但命令侧不被半成品覆盖——失败收敛为"提示 + 保持"。

### 5.3 防抖解析的 gate

现有防抖 useEffect 增加 `activeTab === "command"` 门槛（依赖数组加 `activeTab`）：表单 Tab 下不对旧 rawCommand 发起无谓 IPC；切回命令 Tab 时 effect 重跑，preview/parseError 按当前 rawCommand 刷新（表单→命令切换写入的新命令被正确解析）。`if (!name && !isEdit) setName(cfg.name)` 的自动命名行为**保持不变**（只在命令 Tab 的粘贴场景触发；§5.1 切换用的 parseCommand 调用点独立于防抖 effect，不触发 setName）。

## 6. 保存路径复用（D3，B1/B7）

保存按钮公共，`handleSave` 按 `activeTab` 取源，两条分支都**复用现有链路，不新增任何后端调用**（F13/F14）：
