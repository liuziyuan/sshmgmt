# 需求基线：转发类型完整支持（-D / -R / -J）

> 状态：已冻结（2026-11-19，用户确认执行范围「三期连做」与验收方式「自动化+人工终验」）
> 基线 commit：43ed390（main）
> 来源：《提案-转发类型完整支持》（accepted，已复制到本 worktree `docs/planning/`）+ 用户阶段 0 两项确认

## 0. 目标

一次 pipeline 内按 **v1.3（-D 动态转发）→ v1.4（-R 远端转发）→ v1.5（-J 多跳）** 顺序完成实现与评审：

- 每期独立升版本号（4 处）、独立验证、commit 分层，保留各自回滚点；
- 每期实施前必须已有该期的实施计划（满足提案「实施前需补充细节章节」约定）；
- 对外发布动作（PR / 合并 main / 打 tag）统一推迟到终态合并询问，由用户决定（见裁决记录第 1 条）。

## 1. 非目标（继承提案 §7，不得实施）

- 内置终端（用户明确不做）。
- 移动端。
- `-W` stdio 转发、agent 转发。
- known_hosts 严格校验（维持 TOFU）。
- 逐行转发规则编辑器（保持「粘贴 ssh 命令 → 解析 → 预览」产品形态）。

## 2. 验收标准

### 2.1 第一期 v1.3（-D）

| # | 条款 | 验证方式 |
|---|---|---|
| A1 | 本机以 SOCKS5 代理经跳板访问仅内网可达服务成功，含内网域名目标（跳板侧解析） | 人工终验 |
| A2 | 断线退避重连后代理端口恢复可用 | 人工终验 |
| A3 | 存量配置升级后原隧道行为不变（旧 JSON 无 kind 字段读为 Local） | 自动化（单测） |
| A4 | 粘贴 `ssh -L 10008:host:3306 -D 1080 user@jump` 建出混合规则隧道 | 自动化（parser 单测）+ 人工终验连通 |
| A5 | 现有单跳 -L 全流程零回归（两阶段认证、密码错误红灯、连接中可打断、:22 预检、公钥上传） | 自动化（编译+既有单测）+ 人工终验抽查 |
| A6 | SOCKS5 协议边界：仅 CONNECT/免认证、IPv4/域名/IPv6 地址、拒绝 BIND/UDP ASSOCIATE、通道失败映射错误码 | 自动化（握手纯函数单测） |

### 2.2 第二期 v1.4（-R）

| # | 条款 | 验证方式 |
|---|---|---|
| B1 | 服务器侧访问远端端口能打到本地服务 | 人工终验 |
| B2 | 重连成功后服务器侧监听自动恢复（重新申请 tcpip-forward） | 人工终验 |
| B3 | 远端端口被服务器拒绝时给可读错误且不无限重连（正确错误归类） | 自动化（错误分类）+ 人工终验 |
| B4 | 规则支持可选服务器侧绑定地址，默认回环；parser 解析 `-R` 各形态 | 自动化（parser 单测） |
| B5 | probe / 杀端口逻辑按类型跳过远端端口（不误杀、不误判） | 自动化（单测） |

### 2.3 第三期 v1.5（-J）

| # | 条款 | 验证方式 |
|---|---|---|
| C1 | 两跳隧道 -L 转发可用 | 人工终验 |
| C2 | 任一跳认证失败的红灯文案指明是哪一跳 | 自动化（文案构造）+ 人工终验 |
| C3 | 中间跳断开触发退避重连（断线信号逐跳接力） | 代码审读 + 人工终验 |
| C4 | 粘贴含 `-J`（逗号分隔多跳）的命令解析正确 | 自动化（parser 单测） |
| C5 | 跳板链模型 `hops: Vec<Hop>` + 存量数据迁移（含测试），旧三字段配置无损升级 | 自动化（迁移单测） |

### 2.4 通用不变式（各期均适用，硬性）

1. 新增监听/连接处理任务不进入断开竞速区间；清理时统一中止，无任务泄漏。
2. 认证失败类 = 红灯不重连；网络类 = 退避重连；新增错误路径必须归对类。
3. 密码类弹窗的取消 = 断开连接（不是仅关 UI）。
4. `tunnel.rs` 保持零警告；每期收口跑 `npx tsc --noEmit`、`cargo build`（零新增警告）、`cargo test` 全绿。
5. UI 文案中文、代码注释英文。
6. `src/types.ts` 与 `src-tauri/src/model.rs` 手动保持字段一致。
7. 版本号 4 处同步（package.json / package-lock.json / src-tauri/Cargo.toml / src-tauri/tauri.conf.json），Cargo.lock 随 `cargo build` 同步。

## 4. 验收方式（用户已确认）

- **自动化**：每期收口跑 `npx tsc --noEmit`、`cargo build`、`cargo test`；单测覆盖上表「自动化」条款。
- **人工终验**：真实跳板机环境的连通性条款（A1/A2/A4/A5 抽查、B1~B3、C1~C3）在终态汇报后由用户执行；终态汇报给出逐条操作清单。
- **主控亲自复跑**：每期实现/评审阶段至少一次完整 tsc / cargo build / cargo test 由主控复跑兜底，subagent 回报只作对照。

- 二三期细节条款（如 `-R` 状态语义、v1.5 迁移的具体形态）由方案阶段细化，偏离提案路线级描述时逐条入裁决记录。
