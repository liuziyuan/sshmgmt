## 5. 剩余风险与人工终验清单

### 已知限制 / 剩余风险

1. **应用无法感知外部 `ssh -R` 进程**：全 Remote 隧道探测恒 Free，不 `mark_external`；混合 `-L + -R` 隧道的外部 -R 部分失联检测不到（B5 语义内的已知限制，实施计划 §6.1 约束 8 已登记）。
2. **tcpip_forward 申请不在竞速区间内**（禁区约束）：Stop 最坏延后「15s × Remote 规则数」，由 15s 超时把窗口变为有界（§6.1 约束 10 已登记）。
3. **L8 残余**：被跳过的「单条 JSON 结构本身损坏」条目在下次保存时不会写回；跨版本未知 kind 已由宽容枚举消除。旧二进制（v1.3）读 `kind:"remote"` 仍会整表清空——**回退到 v1.3 前先备份 `tunnels.json`**（macOS：`~/Library/Application Support/sshmgmt/tunnels.json`）或先删除含 `-R` 的隧道。
4. **地址规范化漂移**：服务器回传的 connected_address 与申请地址不一致时，分发任务只 warn + drop（不做猜测性路由），该条远端连接失败但不影响隧道。
5. **cancel 失败仅记日志**：连接关闭会撤销服务器侧监听，符合方案。
6. **`-R 0` 端口不做列表常驻回填**：用户需从 success notice 读取实际端口；重连后端口可能变化并再次提示（裁决最小形态）。

### 人工终验清单（由用户在真实跳板机环境执行）

- **B1**：服务器侧 `curl 127.0.0.1:<R端口>` 打到本机服务；再验一条带 `remote_bind`（如 `-R 0.0.0.0:8080:localhost:3000`）的规则（需服务器 `GatewayPorts clientspecified`）。
- **B2**：断开/杀掉跳板会话 → 观察退避重连 → 服务器侧同一端口再次可用。
- **B3**：先在服务器侧预占远端端口（如 `python3 -m http.server 8080`）再连接 → 红灯、文案含端口、不再自动重连。
- **B4/B5 抽查**：一条混合 `-L + -R` 隧道的探测/连接行为；确认本地同号进程不被误杀。
- **-R 0 抽查**：`-R 0:localhost:<服务端口>` 连接后从 notice 读到实际端口，服务器侧 `ss -ltn` 可见。
- **A5 全量回归抽查**：两阶段认证、密码错误红灯、连接中（黄灯）点断开立即生效、`:22` 预检、公钥上传各一次。
