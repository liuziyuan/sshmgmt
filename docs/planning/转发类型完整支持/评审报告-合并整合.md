## 三、问题清单

### P2-1 回填路径绕过了 `canEditInForm` 守卫，多跳 / `-R` 可被静默降级

**证据**

- 守卫定义仅依据「打开时的编辑目标」：`src/components/TunnelEditor.tsx:57-60`（`canEditInForm`）、`:66`（`formLocked = isEdit && !canEditInForm(editTarget.config)`）。
- 切 Tab 回填：`src/components/TunnelEditor.tsx:132-158`，其中 `:152` 直接 `setFormState(configToFormState(cfg))`，**对解析结果不做任何可表达性检查**，也没有告警。
- 回填转换会丢弃 kind 与跳数：`src/components/tunnelEditorForm.ts:210-223`（`configToFormState` 只取 4 个跳板机字段 + 每条 forward 的 3 个端口/主机字段，`ForwardRow` 结构见 `:9-13`，无 `kind`、无 `hops`）。
- 反向拼装恒为 `-L`：`src/components/tunnelEditorForm.ts:192-197`。

**可复现路径**

1. 新增隧道（`isEdit === false` → `formLocked` 恒为 false），记忆 Tab 为「粘贴命令」或手动从表单切到命令；
2. 粘贴多跳命令 `ssh -J a@h1,b@h2 -L 8080:db:5432 c@h3`，预览正确显示 3 跳；
3. 点「表单填写」→ `parseCommand` 成功 → `configToFormState` 把 3 跳压成 1 个跳板机、规则仍是 local → 表单校验全部通过；
4. 点保存 → 实际创建的是**单跳** `-L` 隧道，跳数丢失且无任何提示；
5. 若此时再切回「粘贴命令」，`handleSwitchTab` 的 `formToCommand` 成功（`:160-162`），`rawCommand` 会被单跳命令覆盖，用户原始粘贴也被丢弃。

编辑模式同样可达：初始为「单跳 + 全 local」的隧道 `formLocked=false`，用户到命令 Tab 把命令改成多跳，再切回表单 Tab → 同样的静默降级，保存后**持久化改写**了原本多跳的隧道。`-R` 规则同理：`configToFormState` 会把 remote 规则映射成看似合法的本地行，保存即变成 `-L`（`-D` 因 `remote_host` 为空会命中表单校验红字，不会静默保存，但多跳与 `-R` 会）。

**影响**：与本 merge 新增守卫要消除的风险同类（静默改写用户隧道语义），且守卫的中文提示（`:281-285`）已明确声明 `-D / -R` 与多跳「表单模式无法完整表达」，但该声明只对打开时即锁定的配置生效。该问题由「V2.0 回填」与「三期类型化配置」组合产生，属本次整合的边界缺口，不是 V2.0 原有 bug。

**建议**：在 `handleSwitchTab` 的 `.then` 内先判 `canEditInForm(cfg)`；不可表达时 `notify("warn", "该命令包含多跳或非本地转发规则，表单模式无法完整表达，未自动回填")` 并 `return`（保持表单原内容），`pendingBackfillRef` 置空。新增模式与编辑模式漂移路径同时覆盖，无需改后端。
