## 1. 问题清单（按严重度排序）

### 1.1 严重（阻断）

### 1.2 中等

#### M-1 R1 的测试没有锁住「调用点」，只锁住了辅助函数

- **证据**：
  - 生产调用点：`src-tauri/src/socks.rs:391` `notify_if_session_dead(&e, || session_error.notify_one());`
  - 辅助函数：`src-tauri/src/socks.rs:256-260`
  - 新增两条测试：`socks.rs:636-662`，直接调用 `notify_if_session_dead(...)`，从未经过 `handle_client` 的调用点。
- **影响**：把 `socks.rs:391` 改回无条件 `session_error.notify_one()`（S1 的原始回归形态）后，**60 条测试仍全部通过**。唯一的间接拦截是非测试构建下 `notify_if_session_dead` 变成 dead code 触发的编译警告（零警告不变式）；一旦后续同时删除该 helper 或为其加 `#[allow(dead_code)]`，回归将完全静默。实施计划 §6.4 声称的缺口「把调用点改回无条件通知，现有测试仍全绿」在实现后**仍未被测试闭合**，变更摘要 §2「R1 门控调用点锁定 | 落实」的表述高于实际。
- **说明**：该缺陷属计划层（回调式调用点本就无法直接单测），实现忠实执行了计划；无运行期缺陷。

#### M-2 `-R` 分发的地址匹配是逐字串比较，地址规范化漂移时静默丢连接

- **证据**：`src-tauri/src/tunnel.rs:626-641` 以 `r.listen_addr == conn.listen_addr && r.listen_port == conn.listen_port` 精确匹配；未命中只 `tracing::warn!`，不做任何回退或提示。申请地址来自 `tunnel.rs:433-436`（`None` → `"localhost"`，`Some("")` 原样传空串）。
- **影响**：若服务器回传的 `connected_address` 与申请串不一致（`"localhost"` ↔ `"127.0.0.1"`、大小写、空串与 `"0.0.0.0"`），该隧道所有 -R 连接都会被丢弃：隧道仍显示绿灯、无任何 banner，用户只能从日志诊断，B1 表现为"服务器侧连上即断"。OpenSSH 服务端按请求地址原样回传（设计附录已论证），风险集中在非 OpenSSH 服务端或代理层。设计 §6.1 约束 4 明确"只 warn + drop、不做猜测性路由"，因此这是**设计已接受的残余风险**，但建议写入终态汇报的已知限制（当前变更摘要 §5.4 已登记类似条目，但未评估"全量 -R 连接不可用"的用户可见性）。
- **判定**：非实现缺陷；风险等级中等，需在终态交付中显式说明。

#### M-3 半开连接重连时，RequestDenied 会把隧道直接置红（与 B2 的边界）

- **证据**：`src-tauri/src/tunnel.rs:210-213` 将 `RequestDenied` 归为 `Fatal`；`run_tunnel` 对 Fatal 直接 `break`（`tunnel.rs:315-321`）。
- **影响**：网络分区/休眠导致旧 TCP 半开时，服务端可能仍持有上一次会话申请的监听端口；客户端 keepalive 判死后自动重连，新会话的 `tcpip_forward` 会收到 `RequestDenied`，隧道**红灯停止**而非退避重试，需用户手动重连。B3 要求"不无限重连"、B2 要求"重连后监听自动恢复"，两者在该场景冲突，方案已锁定 RequestDenied→Fatal，实现无误；但 B2 的人工终验清单只覆盖"断开/杀掉跳板会话"（服务端会立即释放端口），覆盖不到半开场景。
- **判定**：设计明确取舍，非实现缺陷；建议终态汇报登记该场景，或将 B2 人工终验增加"客户端网络中断后恢复"一档。
