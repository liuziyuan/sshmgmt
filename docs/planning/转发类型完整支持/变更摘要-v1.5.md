### 硬性约束逐条核对

| 约束 | 结论 | 证据 |
|---|---|---|
| forward_tx 只注入最终跳 | 落实 | `hop_forward_tx = if is_final { ... } else { None }`，phase1/phase2 均使用该值 |
| tcpip_forward 走最终跳 | 落实 | 远程申请循环 `&mut chain[final_idx]`，失败 cancel 也用 `chain[final_idx]` |
| 聚合任务在建立会话竞速 select 之外、等待 select 之前 spawn | 落实 | `tasks.push(tokio::spawn(forward_first_signal(...)))` 位于 establish 返回后、监听循环前；TaskSet 托管 |
| 清理 abort → cancel → 最终跳 disconnect → 中间跳逆序 | 落实 | 正常清理与 `cleanup_failed_bind` 均按此顺序 |
| 单跳路径行为/文案逐字等价 v1.4（A5） | 落实 | 单跳 hops 由 parser 生成且等于 legacy；认证失败文案单测逐字断言；公钥 notice 单跳分支保留原文；密码 payload 单跳无新字段；`:22` 预检条件表达式未变 |
| 每跳两阶段、独立 MaxAuthTries | 落实 | 每跳 phase1 公钥连接（失败显式 disconnect）→ phase2 新建连接/新通道走密码/KBI |
| keepalive 每跳独立 | 落实 | 首跳 `connect` 与后续 `connect_stream` 共用同一带 keepalive 的 `Arc<Config>` |
| 每跳 15s 超时 | 落实 | `connect_jump_host` 与 `open_hop_session`（开通道+握手整段）均 `JUMP_CONNECT_TIMEOUT` |
| 空链防御 | 落实 | `establish_session` 空 hops → `Fatal("隧道缺少跳板配置")`；`connect_and_forward` 对空 chain 再做一次防御 |
| -R × -J | 落实 | forward_tx/tcpip_forward/cancel/dispatch 均走最终跳；失败路径逆序断链；重连仍由 `run_tunnel` 循环重跑自动恢复 |
| 迁移幂等 + 失败不阻断启动 | 落实 | `migrate_hops` + `ensure_hops` 幂等；保存失败仅 warn |

## 5. 剩余风险与人工终验清单

### 已知限制 / 剩余风险

1. **-J 语法范围**：仅 `[user@]host[:port]`，不支持 `none`/通配等 OpenSSH 扩展（实施计划 §11.1 第 11 条）。
2. **最坏建链/认证等待**：每跳 15s 建连超时 + 每跳密码最长 5 分钟等待，多跳最坏为「15s × 跳数 + 5min × 需人工输入的跳数」；期间 Stop/Reconnect 仍可立即打断（竞速结构未变）。
3. **transfer 的 `target_user` 键既有不一致**：导出/导入沿用 `first_hop()` 键，运行期实际键是目标机 `host:port`；导出格式只有单值 `target_user` 无法表达多目标（v1.2 起既有，v1.5 仅机械迁移，§11.3 已登记）。
4. **回滚镜像**：旧版本（v1.4）读新配置时按 legacy 三字段得到「首跳单跳近似」——多跳隧道回退后只会直连入口跳、转发不可用但不崩溃。**回退前建议先备份 `tunnels.json`**。
5. **-R 已知边界继承**：v1.4 的地址漂移静默丢连接、半开重连 `RequestDenied` 直接红灯语义不变。
6. **聚合任务空 rx 分支**：理论上不可达（空链已 Fatal）；若发生会立即按「SSH session closed」重连，不 panic、不泄漏。

### 人工终验清单（由用户在真实跳板机环境执行）

- **C1**：两跳 `ssh -J u1@h1 -L 10008:target:3306 u2@h2`（hops = h1 → h2）建立后本地端口可用，转发经最终跳 h2 到达 target。
- **C2**：两跳隧道故意输错**第 2 跳**密码 → 红灯文案含「第 2/2 跳」；单跳输错密码 → 文案与 v1.4 完全一致；多跳密码弹窗标题显示「第 N/M 跳 · host」。
- **C3**：连接后杀掉**中间跳**会话 → 黄灯 `Reconnecting` → 恢复后转发可用；杀最终跳同样。
- **A5 全量回归抽查**：单跳 -L/-D/-R 各一次（两阶段认证、密码错误红灯、连接中黄灯点断开立即生效、`:22` 预检、公钥上传、`-R 0` notice）。
- **-R × -J 抽查**：两跳 + `-R 8080:localhost:<服务端口>`，服务器侧 `curl 127.0.0.1:8080` 打到本机服务；断最终跳后重连，服务器侧监听恢复。
- **导出/导入抽查**：两跳隧道保存两跳密码 → 导出 → 另一环境导入 → 连接不再弹两跳密码。
- **迁移抽查**：用 v1.4 生成的 `tunnels.json` 启动 v1.5，确认单跳隧道照常连接且配置被补上 `hops`；`-R` 隧道行为不变。
