### 1.3 建议（2 项）

#### P2：开发态 StrictMode 会让迁移警告重复弹两条

- **证据**：`src/main.tsx:6` 使用 `<React.StrictMode>`；`src/App.tsx:83` 在挂载 effect 内直接调用 `getStartupWarning().then(... notify("warn", w))`，effect 依赖数组为 `[reload, notify]`（`src/App.tsx:109`）。
- **触发条件**：`npm run tauri dev`（React 19 开发态对 effect 执行两次 mount 模拟）；迁移产生警告时。
- **后果**：顶部出现两条内容相同的常驻 warn banner（各有独立 id）。生产构建（`npm run build` 产物）StrictMode 不会双跑 effect，**用户侧不受影响**。
- **建议**：如希望开发态也干净，可在前端用 `useRef` 做一次性守卫；`OnceLock` 后端无法清除，不建议为此改后端。非必须。

#### P3：迁移失败文案未给出旧目录绝对路径，可操作性弱于实施计划的风险缓解描述

- **证据**：`src-tauri/src/store.rs:52-56`（创建新目录失败）文案为「配置目录迁移失败，将以空配置启动（旧数据仍保留）：{e}」，未给出旧目录位置；`src-tauri/src/store.rs:71-75`（部分复制失败）只给出**新目录**路径，要求「手动将旧目录中的对应文件复制到新目录」，但未给出旧目录绝对路径。实施计划 §5 风险 2 的缓解表述为「警告文案给出旧目录位置与手动复制路径」。
- **触发条件**：B6 的迁移失败场景（评审已用悬空软链沙箱复现，见 §4）。
- **后果**：用户知道迁移失败、旧数据还在，但不知道旧数据在哪，难以按提示自救。B6 本身（不崩溃、不丢旧数据、可感知）仍满足，故不构成阻断。
