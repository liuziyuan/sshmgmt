# 需求基线：改名 portunnel 与数据迁移

> 冻结方式：讨论轮用户已逐项拍板（原提案 status: accepted），按已确认内容冻结，标注「按讨论轮确认冻结」
> 需求权威来源：本文件。主工作区的原提案文档（untracked）内容已完整并入，后续以本文件为准
> 基线 commit：ed9fede2dfc521c2f8353b80be0dea483789ea19（V2.0 分支）

## G. 目标

1. 项目更名为 portunnel：GitHub repo 名、安装包/应用名（productName）、crate/npm 包名、文档与 CI 文案全部换新。
2. 老用户平稳过渡：升级后隧道配置、分组顺序、折叠状态、钥匙串密码**零操作**延续。
3. 版本 2.0.0，走完整发布流程（PR → merge → tag 触发 CI → 人工 Publish）。

## N. 非目标

- 不迁移钥匙串条目（service 名不变，密码自动延续）。
- 不改导出格式标识与版本（保持 `"sshmgmt-tunnels"` v1）。
- 不删除旧数据目录。
- 不改隧道连接状态机（tunnel.rs）、认证流程、转发逻辑。
- 不实施其他两份既有提案（新增隧道表单模式已实施、转发类型完整支持）的功能内容。

## A. 验收标准

| 编号 | 标准 |
|---|---|
| B1 | 老用户（存在旧数据目录）升级 2.0.0：首次启动后隧道列表、分组顺序、折叠状态、已存密码全部可用，零手动操作 |
| B2 | 迁移后旧目录仍存在且内容不变；回滚装 1.2.0 一切照旧 |
| B3 | 新装用户（无旧目录）：直接使用 `portunnel/` 目录，行为与旧版一致 |
| B4 | 导出文件双向互通：1.2.0 导出的文件可导入 2.0.0；2.0.0 导出的文件可导入 1.2.0 |
| B5 | identifier（`com.sshmgmt.app`）、钥匙串 service（`"sshmgmt"`）、导出格式标识（`"sshmgmt-tunnels"`）三个字符串在代码中不变 |
| B6 | 迁移失败不崩溃、不丢旧数据，且用户可感知（接入现有 banner 系统） |
| B7 | `npm run build`、`cargo build`、`cargo test` 通过；tunnel.rs 保持零警告 |

## C. 约束与关键决策

| 编号 | 约束 |
|---|---|
| C1 | 数据目录迁移规格（路线 B）：启动时一次性判定——新目录存在→直接用新目录；新目录不存在且旧目录存在→将旧目录三个文件（tunnels.json、group_order.json、collapsed_groups.json）**复制**到新目录，之后用新目录；都不存在→用新目录。复制非移动；旧目录保留原样不删；失败降级为空配置启动、不崩溃；此后永远只读写新目录 |
| C2 | 底层保留清单：identifier、钥匙串 service、导出格式标识三样**全部不变** |
| C3 | 显示名划分：窗口标题、README 标题维持「SSH 隧道管理器」；productName → `portunnel` |
| C4 | 版本号四处同步为 2.0.0（npm version 一次改 package.json+lock；Cargo.toml、tauri.conf.json 手改；cargo build 同步 Cargo.lock）；发布流程照 CLAUDE.md，tag 是触发发布的唯一步骤不能省 |
| C5 | repo 名 `portunnel`（GitHub 撞名已实测：3 个同名仓库全 0 星）；README/CLAUDE.md 链接、git remote 同步更新 |
| C6 | 发布文案要点：app 路径改为 `/Applications/portunnel.app`（README 的 xattr 命令同步）；说明由 sshmgmt 更名而来、配置与密码自动延续；提醒安装后卸载旧版（新旧并存期间数据各自独立会分叉） |
| C7 | 迁移失败的用户通知必须接入现有 banner 系统（`notify("warn", ...)`），具体通道由方案设计 |
| C8 | macOS 数据目录实际位置为 `~/Library/Application Support/sshmgmt/`（CLAUDE.md 现描述只对 Linux 成立），文档修正时顺带写清；迁移逻辑不得依赖硬编码绝对路径，必须基于 `dirs::config_dir()` 派生 |

## D. 实施起点清单（来自原提案 §8，方案阶段可细化，不得缩减范围）

1. tauri.conf.json：productName → portunnel；version → 2.0.0；identifier 不动
2. Cargo.toml：name → portunnel、lib name → portunnel_lib；main.rs 引用同步；cargo build 同步 Cargo.lock
3. package.json / lock：npm version 2.0.0 + name → portunnel
4. store.rs：config_dir 返回 portunnel/；一次性迁移函数（C1 规格）；失败接 banner；启动最早点调用
5. lib.rs：日志 EnvFilter → "portunnel=debug"（跟随新 crate 名）
6. api.ts：导出默认文件名 → tunnels.portunnel.json、过滤器扩展 → portunnel.json
7. transfer.rs：测试临时目录名 → portunnel-transfer-tests；EXPORT_FORMAT 不动
8. README.md：标题、安装包文件名表格、macOS"已损坏"提示、Releases 链接
9. CLAUDE.md：名称、链接、数据路径描述修正（C8）、钥匙串约定段落核对
10. release.yml：releaseName → portunnel vX；releaseBody 按 C6 更新
11. GitHub repo 改名 + remote 更新（需人类执行/授权）
12. 验证：npm run build、cargo build、cargo test + 迁移三态手动验证
13. 发布：PR → merge → tag v2.0.0 → 人工 Publish（需人类参与）
