## 2. 关键设计决策（每条含「为什么」）

### D1 目录迁移放在 store.rs，核心抽成纯函数 `migrate_between(base, legacy_name, new_name)`

**为什么**：
- `config_dir()` 是全仓唯一的数据目录派生点，所有读写都经过它；迁移逻辑与目录派生天然同域，放 store.rs 改动面最小（`tunnels_path()` 等 3 个路径函数自动跟随新目录名，`commands.rs` 的 8 处 store 调用点零改动）。
- 纯函数化（目录以参数传入，不读真实 `$HOME`）让 `cargo test` 能直接覆盖 C1 三态、复制非移动（B2）、幂等、部分失败（B6），不依赖用户家目录的真实状态，也把基线 D12 的「迁移三态手动验证」压缩为「单测 + 一次冒烟」。

### D2 迁移调用点 = `run()` 最前面（`EnvFilter` 之后、`load_tunnels()` 之前），并要求此后不得在迁移前做任何目录写入

**为什么**：
- C1 三态判定以「新目录是否存在」为依据。所有 `save_*` 都会 `create_dir_all(config_dir())`——**只要迁移之前发生过任何一次写，新目录就会被凭空创建，三态判定永久失效，老用户数据永不迁移**（B1 被破坏）。现有启动序列里最早的写是 `migrate_env_case` 的条件性 `save_tunnels`（`lib.rs:99`），因此迁移必须插在它之前。
- `run()` 是同步顺序执行，迁移完成后才轮到 `load_tunnels()` 与后续 command 事件，天然满足「先迁移、后读写新目录」（P1、P5），不需要任何锁。

### D3 迁移失败通知 = 后端 `OnceLock` 存警告 + 新增 query command `get_startup_warning` + 前端挂载时拉取转 `notify("warn", ...)`

**为什么**（对比过两条路）：
- 备选 B：迁移后延迟 emit `tunnel://notice`（仿照 `detect_existing` 的 1200ms sleep 先例）。否决——该通道依赖「webview 已挂载且 listener 已注册」，sleep 是竞态赌注；`detect_existing` 丢了消息只是状态灯不准，而 B6 是硬性「用户可感知」，竞态丢消息不可接受。
- 选定 A：迁移发生在 `run()`（无 AppHandle、webview 未挂载），把警告存进进程级 `OnceLock<String>`；前端 `App.tsx` 现有挂载 effect（`App.tsx:80-107`，依赖稳定只跑一次）里 `invoke("get_startup_warning")`，非空则 `notify("warn", ...)`。时序确定（command 必然晚于迁移完成）、复用现有 banner（C7）、前端只需约 3 行。
- 警告语义：`OnceLock` 只在迁移产生警告时被 set；每次启动重跑迁移（判定幂等，见 D4），持续失败的场景每次启动都会再提示一次，一次性失败只提示一次——无需额外去重状态。

### D4 复制规格细化：三个文件逐个 best-effort 复制；部分失败也收敛为「迁移完成 + 警告」，不回滚、不重试

**为什么**：
- C1 原文「失败降级为空配置启动、不崩溃」确定了失败语义是降级而非中止。部分失败时：新目录已建立（`create_dir_all` 已成功），下次启动三态第一支「新目录存在→直接用」→ 不再重试。这是 C1 规格的直接推论，追加重试逻辑反而违反「此后永远只读写新目录」的简洁性。
- `create_dir_all` 本身失败时新目录大概率不存在，下次启动会自然重试整个迁移——持续失败则持续提示，行为自洽，无需记忆状态。
- 复制仅限 C1 列举的三个 JSON 文件；旧目录里其他文件一律不碰（避免过度设计）。源文件若缺失（如用户从未设过分组顺序）跳过即可。
- 单个源文件损坏（非法 JSON）不影响迁移：copy 是字节级复制，读取侧已有 `unwrap_or_default()` 降级，与旧行为一致。

**为什么 transfer.rs 测试 fixture 里的 `"sshmgmt-tunnels"` 不能顺手改成变量引用以外的形式**：这些字面量是「旧版本导出的文件」的模拟，改了它们就测不出「新版能读旧格式」这个真实约束（B4）。`EXPORT_FORMAT` 常量本身不动，fixture 保持字面量恰好构成对 B5 的回归测试。

### D6 发布顺序：PR 合并 → GitHub repo 改名 → 更新 remote → tag v2.0.0 → 人工 Publish

**为什么**：tag 推送触发的 `tauri-action` 会把草稿 Release 建在**当时**的 repo 名下，且 releaseBody 与 README 链接均指向 `liuziyuan/portunnel`。先改名再 tag，Release 页面 URL、安装包下载链接、文档三者一次对齐；若先 tag 后改名，草稿 Release 虽会随仓库改名保留，但 CI 运行记录、通知、缓存都会带着旧名制造混乱。GitHub repo 改名后旧 URL 301 重定向，改 remote 前的任何 git 操作仍可用，顺序无阻塞风险。

### D7 发布文案中「数据独立」的精确表述

基线 C6 说「新旧并存期间数据各自独立会分叉」。事实是：**配置目录独立**（`portunnel/` vs `sshmgmt/`），**钥匙串共享**（service 名不变，C2）。方案把文案落为「配置各自独立、会各自分叉」，避免「数据完全独立」的不准确表述（密码其实互通）。这是对 C6 要点的措辞细化，不改变其意图（提醒卸载旧版）。

## 3. 详细设计

### 3.1 store.rs：目录常量、迁移纯函数、启动警告存储（S1）

```rust
// 目录名常量化，config_dir() 是全仓唯一派生点
pub const APP_DIR_NAME: &str = "portunnel";
pub const LEGACY_DIR_NAME: &str = "sshmgmt"; // 保留只读：迁移源，永不写入
const MIGRATED_FILES: [&str; 3] = ["tunnels.json", "group_order.json", "collapsed_groups.json"];

fn base_dir() -> PathBuf {
    dirs::config_dir()
        .unwrap_or_else(|| dirs::home_dir().unwrap_or_else(|| PathBuf::from(".")))
}
fn config_dir() -> PathBuf { base_dir().join(APP_DIR_NAME) }
fn legacy_config_dir() -> PathBuf { base_dir().join(LEGACY_DIR_NAME) } // 仅迁移函数使用

/// One-shot legacy→new data-dir migration (spec C1).
/// MUST run before any create_dir_all(config_dir()) — an early write would
/// create the new dir and the three-state check would never fire again (P1).
pub fn migrate_legacy_data_dir() -> Option<String> {
    migrate_between(&base_dir(), LEGACY_DIR_NAME, APP_DIR_NAME)
}

/// Pure, testable core. States:
///   new dir exists            -> None (use new dir; legacy untouched)
///   new missing, legacy exists-> copy the three JSON files (copy, NOT move)
///   both missing              -> None
/// Any failure -> Some(warning message), keep going (empty-config startup).
pub(crate) fn migrate_between(base: &Path, legacy_name: &str, new_name: &str) -> Option<String> {
    let new_dir = base.join(new_name);
    if new_dir.exists() { return None; }
    let legacy_dir = base.join(legacy_name);
    if !legacy_dir.exists() { return None; }
    if let Err(e) = std::fs::create_dir_all(&new_dir) {
        return Some(format!("配置目录迁移失败，将以空配置启动（旧数据仍保留）：{e}"));
    }
    let mut failures = Vec::new();
    for file in MIGRATED_FILES {
        let src = legacy_dir.join(file);
        if !src.exists() { continue; }
        let dst = new_dir.join(file);
        if let Err(e) = std::fs::copy(&src, &dst) {
            failures.push(format!("{file}: {e}"));
        }
    }
    if failures.is_empty() { None } else {
        Some(format!(
            "部分配置文件迁移失败，缺少的配置将以空内容启动。旧数据仍完整保留，可手动将旧目录中的对应文件复制到新目录 {}。失败详情：{}",
            new_dir.display(),
            failures.join("；")
        ))
    }
}
```

### 3.2 lib.rs：启动接入（S2）

```rust
pub fn run() {
    tracing_subscriber::fmt()
        .with_env_filter(
            tracing_subscriber::EnvFilter::try_from_default_env()
                .unwrap_or_else(|_| tracing_subscriber::EnvFilter::new("portunnel=debug")), // 跟随新 crate 名
        )
        .init();

    // Earliest possible point: must precede load_tunnels() and any save_*(),
    // because both create the config dir and would defeat the three-state check.
    if let Some(warning) = store::migrate_legacy_data_dir() {
        tracing::warn!("legacy data dir migration: {}", warning);
        store::set_startup_warning(warning);
    }

    let mut tunnels = load_tunnels();
    migrate_env_case(&mut tunnels); // 不变：数据内迁移，发生在目录迁移之后
    ...
}
```
