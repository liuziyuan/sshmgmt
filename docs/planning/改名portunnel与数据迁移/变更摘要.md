## 6. 偏离与原因

1. **`migrate_legacy_data_dir` 的 base 派生**：实现为 `legacy_config_dir().parent()` 而非直接 `base_dir()`。原因：实施计划要求 `legacy_config_dir()` 仅被 `migrate_legacy_data_dir` 引用；用其父目录派生可同时满足该约束并避免死代码警告。行为与 P9 一致（无硬编码路径）。
2. **README 第二段措辞**：未重复「旧版 sshmgmt」字面量，改为「安装过旧版」。原因：实施计划步骤 14 判定要求 `grep 'sshmgmt' README.md` 仅剩 1 处；语义由第一段「由 sshmgmt 更名而来」承担，C6/D7 意图不变。
3. **npm 依赖键序**：`npm version`/`npm pkg set` 会按字母序重写 package.json 依赖块，已手工恢复原键序以缩小 diff；未改任何版本范围。
4. **`npm install --package-lock-only --offline`** 实际执行成功（离线），lock 的 name/version 由工具同步，未手改。

## 7. 遗留风险（≤3）

1. **GUI 相关验证缺口**：B1 列表/分组/折叠的界面显示、B3「界面新增隧道后落盘」、B6 常驻 warn banner 的视觉呈现无法在无显示自动化环境作证，需人工冒烟确认。
2. **部分复制失败不重试**：按 C1/D4 设计，部分文件复制失败后新目录已建立，后续启动走「新目录存在」分支不再重试；用户可能长期缺非关键配置，仅依赖启动警告与旧目录手动复制指引。
3. **跨版本人工互导未执行**：B4 的「1.2.0 ↔ 2.0.0 安装包互导」需下载旧版安装包，属外部/付费操作，本次仅以 transfer 单测（旧格式 fixture）作证。
