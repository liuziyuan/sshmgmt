# 设计文档：多语言支持（i18n，中/英）

> 输入：`docs/planning/多语言/需求基线.md`（G1-G6 / A1-A8 / N1-N6 / C1-C7 / D1-D7 / H1-H3，全部冻结）。本设计不推翻其中任何一条；C3（不改业务逻辑）为红线。
> 代码事实基线：本文所有文件/方法/行号均来自对 worktree（基线 4fbb48d）源码的实读；grep 统计见 §8 核对记录。

## 1. 总体架构

### 1.1 设计原则

1. **后端零文案**：Rust 不再构造任何用户可见自然语言文本，只构造「消息码 + 插值参数」（`Msg` 枚举）。日志（`tracing`）不是用户文案，保持英文，用 `Msg` 的 `Debug` 输出。
2. **前端单一翻译出口**：`src/locales/{zh,en}.json` 是全部用户文案的唯一来源；zh 是默认与回退语言（A4/C6）。
3. **三条消息通道都码化，传输结构变化最小化**：事件（state-changed / notice / password-required）、命令返回（Err 侧）、命令拉取（startup warning / ImportSummary.warnings）——全部把「字符串字段」换成「`LocalizedMessage` 字段」，事件名、命令名、通道拓扑一律不动（C3）。
4. **历史 banner 不重翻（C7）**：banner 存储层仍是「渲染后的字符串」，`notify()` 在收到消息的瞬间用**当时的语言**渲染。语言切换后旧 banner 保留原文，新消息用新语言——现状代码结构天然满足，无需额外机制。

### 1.2 消息流（改造后）

```
┌─ 后端（Rust，语言无关）────────────────────────────┐
│ tunnel.rs/parser.rs/commands.rs/store.rs/transfer.rs │
│   构造 Msg::{code, params}                           │
│   ├→ TunnelState::Failed(Msg)   ──事件 tunnel://state-changed
│   ├→ emit_notice(Msg)           ──事件 tunnel://notice
│   ├→ password_payload(prompt: Msg) ──事件 tunnel://password-required
│   ├→ command Err: LocalizedMessage   ──invoke 返回值 Err 侧
│   └→ get_startup_warning() -> Option<Msg> / ImportSummary.warnings: Vec<Msg>
└──────────────────────────────────────────────────┘
                      ↓ serde JSON
┌─ 前端（React，语言唯一感知方）──────────────────────┐
│ api.ts: toMessage(e) 归一化 + renderMsg(m) = i18n.t(`msg.${code}`, params) │
│ App.tsx notify(): 渲染期用当前语言定格为字符串（C7）  │
│ 组件渲染路径：useTranslation().t(key)                 │
│ 语言切换：changeLanguage → React 重渲染               │
│           → invoke("set_window_title") / invoke("rebuild_tray") │
└──────────────────────────────────────────────────┘
```

## 2. 核心设计

### 2.1 消息码枚举 `Msg`（model.rs ↔ types.ts，C1）

**Rust 定义**（`src-tauri/src/model.rs` 新增，置于 `TunnelState` 之后）：

```rust
/// Structured user-facing message: a stable code plus interpolation params.
/// The backend never renders user-visible text; the frontend locales file
/// translates `code` (key: `msg.<camelCase variant>`) and interpolates
/// `params`. Logs keep using Debug output (English).
/// MUST stay field-identical with `Msg` in src/types.ts (see CLAUDE.md C1).
#[derive(Debug, Clone, Serialize, Deserialize, PartialEq)]
#[serde(tag = "code", content = "params", rename_all = "camelCase", rename_all_fields = "camelCase")]
pub enum Msg {
    // ── 隧道生命周期 / 连接错误（tunnel.rs）──
    NoSupportedForwards,                                   // 原"该隧道没有可用的转发规则…"
    MissingJumpConfig,                                     // 原"隧道缺少跳板配置"（2 处复用）
    ReconnectRequested,                                    // 原"Reconnect requested"（2 处复用）
    SshSessionClosed,                                      // 原"SSH session closed"
    SshChannelError,                                       // 原"SSH channel error"（含 SOCKS 通道死亡）
    BindFailed { addr: String, detail: String },           // 原"Cannot bind {addr}: {e}"

    // ── 远端转发 -R（tunnel.rs）──
    RemoteForwardTimeout { port: u16, timeout_secs: u64 }, // 原"申请远端转发监听超时（端口 X，Ns）"
    RemotePortDenied { port: u16 },                        // 原"远端端口 X 被服务器拒绝…"（Fatal）
    RemoteForwardFailed { port: u16, detail: String },     // 原"申请远端转发端口 X 失败: {e}"
    RemotePortOutOfRange { port: u32 },                    // 原"服务器分配的远端端口超出范围: N"
    RemotePortAllocated { addr: String, port: u16 },       // success notice"服务器已分配远端端口 addr:port"

    // ── 连接步骤错误（tunnel.rs；jump=入口直连/链上跳，target=二级登录）──
    JumpConnectTimeout { host: String, port: u16, timeout_secs: u64 },
    JumpConnectFailed { detail: String },
    HopChannelOpenFailed { host: String, port: u16, detail: String },
    HopConnectFailed { host: String, port: u16, detail: String },
    HopConnectTimeout { host: String, port: u16, timeout_secs: u64 },
    TargetChannelOpenFailed { host: String, port: u16, detail: String },
    TargetConnectFailed { detail: String },

    // ── 认证（tunnel.rs；分类与两阶段流程不变，只换消息载体）──
    JumpKeyAuthError { detail: String },                   // 阶段一公钥底层错误（Retriable）
    JumpPasswordPhaseError { detail: String },             // 阶段二密码底层错误（Retriable）
    TargetKeyAuthError { detail: String },
    TargetPasswordPhaseError { detail: String },
    /// 原 hop_auth_failure_msg()：单跳"跳板机 u@h 认证失败（用户名或密码错误）"，
    /// 多跳加 hopIndex/hopTotal（"第 i/n 跳 …"）。Fatal。
    HopAuthFailed {
        user: String,
        host: String,
        #[serde(skip_serializing_if = "Option::is_none")]
        hop_index: Option<usize>,
        #[serde(skip_serializing_if = "Option::is_none")]
        hop_total: Option<usize>,
    },
    TargetAuthFailed { host: String },                     // 原"目标主机 X 认证失败（用户名或密码错误）"（Fatal）

    // ── 成功/警告 notice（tunnel.rs emit_notice 5 处）──
    PubkeyUploaded {
        host: String,
        #[serde(skip_serializing_if = "Option::is_none")]
        hop_index: Option<usize>,
        #[serde(skip_serializing_if = "Option::is_none")]
        hop_total: Option<usize>,
    },                                                     // 原"已上传公钥到跳板机 X，下次免密连接"（单/多跳两分支合并）
    PubkeyUploadFailed { /* 同上字段 */ host: String, hop_index: Option<usize>, hop_total: Option<usize> },
    TargetPubkeyUploaded { host: String },
    TargetPubkeyUploadFailed { host: String },

    // ── 密码弹窗 prompt（tunnel.rs password_payload）──
    PromptJumpPassword { user: String, host: String },     // 原"Password for u@h"
    PromptTargetLogin { host: String },                    // 原"Login to target host h"

    // ── 解析错误（parser.rs）──
    ParseTokenizeFailed { detail: String },                // shell_words::split 失败（隐式第 17 处）
    ParseFlagNeedsArg { flag: String },
    ParseInvalidPort { value: String },
    ParseNoDestination,
    ParseNoForwards,
    ParseInvalidLocalPort { value: String },
    ParseInvalidRemotePort { value: String },
    ParseInvalidLSpec { spec: String },
    ParseInvalidDSpec { spec: String },
    ParseInvalidRSpec { spec: String },
    ParseInvalidRListenPort { value: String },
    ParseREmptyTarget { spec: String },
    ParseInvalidRTargetPort { value: String },
    ParseJEmptyHop { spec: String },
    ParseJEmptyHost { hop: String },

    // ── 命令层（commands.rs）──
    TunnelNotFound,                                        // 原"Tunnel not found"（3 处复用）
    NoPendingPassword,                                     // 原"No pending password request…"
    ImportKeychainFailed { name: String, detail: String },
    ImportHopKeychainFailed { name: String, hop_index: usize, hop_total: usize, detail: String },
    ImportTargetUserKeychainFailed { name: String, detail: String },
    /// 兜底：底层 IO/序列化错误在 command 边界包装；前端 toMessage 对
    /// 非 JSON 错误也落到此 code。文案"操作失败：{{detail}}"。
    CommandFailed { detail: String },

    // ── 启动迁移警告（store.rs，经 get_startup_warning 拉取）──
    MigrationFailed { legacy_dir: String, detail: String },
    MigrationPartialFailed { legacy_dir: String, new_dir: String, failures: Vec<String> },

    // ── 导入/导出（transfer.rs）──
    ExportSerializeFailed { detail: String },
    ExportWriteFailed { path: String, detail: String },
    ImportReadFailed { path: String, detail: String },
    ImportInvalidJson { detail: String },
    ImportUnknownFormat { format: String, expected: String },
    ImportUnsupportedVersion { version: u32, max_version: u32 },
    ImportEmptyId,
    ImportEmptyName,

    // ── UI 支撑命令（rebuild_tray / set_window_title）失败路径 ──
    TrayMissing,
    TrayUpdateFailed { detail: String },
    MainWindowMissing,
    SetTitleFailed { detail: String },
}
```

变体合计 **65 个**（§5 入口矩阵逐处对应；`Option` 字段一律 `skip_serializing_if = "Option::is_none"`，与现有 `password_payload` 可选字段风格一致）。

**serde 序列化形态**（adjacently tagged，与现有 `TunnelState` 同风格）：

```json
{"code": "missingJumpConfig"}
{"code": "remotePortDenied", "params": {"port": 8080}}
{"code": "hopAuthFailed", "params": {"user": "u", "host": "h", "hopIndex": 2, "hopTotal": 3}}
```

> `rename_all_fields` 需要 serde ≥ 1.0.186；已核对 Cargo.lock 为 serde 1.0.228，满足。

**TS 对应类型**（`src/types.ts` 新增，判别联合，编译期锁死 code 拼写）：

```ts
/** 与 src-tauri/src/model.rs 的 Msg 手动保持一致（C1）。 */
export type Msg =
  | { code: "noSupportedForwards" }
  | { code: "missingJumpConfig" }
  | { code: "reconnectRequested" }
  | { code: "sshSessionClosed" }
  | { code: "sshChannelError" }
  | { code: "bindFailed"; params: { addr: string; detail: string } }
  | { code: "remoteForwardTimeout"; params: { port: number; timeoutSecs: number } }
  // …其余变体与 Rust 枚举一一对应，此处从略（实现时全量展开）…
  ;

/** 宽松形态：事件/命令边界上的消息值（运行时校验走 renderMsg 兜底）。 */
export interface LocalizedMessage {
  code: Msg["code"];
  params?: Record<string, unknown>;
}
```

**日志策略**：`tracing` 调用点改用 `{:?}` 打印 `Msg`（如 `tracing::warn!("Tunnel {} fatal: {:?}", id, msg)`），日志保持英文、不含用户文案，`tunnel.rs` 保持零警告（C5）。不手写英文 `log_text()`（65 变体的手写 match 收益低于成本，Debug 输出已含字段名，开发者可读）。

### 2.2 消息在现有事件/命令结构上的落点（逐通道）

| 通道 | 现结构 | 改造后 | 改动文件 |
|---|---|---|---|
| 状态事件 | `TunnelState::Failed(String)`（model.rs:239，`#[serde(tag="type", content="message")]`） | `TunnelState::Failed(Msg)`；JSON 形态从 `"message":"文本"` 变为 `"message":{"code":…,"params":…}`；其余 5 个状态不变 | model.rs、types.ts |
| notice 事件 | `emit_notice(app,id,level,message:&str)`（tunnel.rs:110）→ `{id,level,message:string}` | `emit_notice(app,id,level,msg:&Msg)`；JSON 的 `message` 字段变 `LocalizedMessage`。事件名 `tunnel://notice` 不变 | tunnel.rs、api.ts |
| 密码弹窗事件 | `password_payload(...)` 的 `prompt: String`（tunnel.rs:1229-1249） | `prompt: Msg`（`PromptJumpPassword`/`PromptTargetLogin`）；`id/layer/host/needUsername/hopIndex/hopTotal` 不变，事件名不变 | tunnel.rs、api.ts |
| 命令 Err 侧 | 全部 command 返回 `Result<_, String>`（`map_err(\|e\| e.to_string())`） | `Result<_, Msg>`；Tauri 要求 Err 实现 Serialize，`Msg` 已 derive。parser 签名改为 `Result<TunnelConfig, Msg>` | commands.rs、parser.rs、api.ts |
| 启动警告 | `get_startup_warning() -> Option<String>` | `Option<Msg>`（`MigrationFailed`/`MigrationPartialFailed`） | store.rs、commands.rs、api.ts |
| 导入摘要 | `ImportSummary.warnings: Vec<String>` | `Vec<Msg>`（Keychain 三变体）；`imported/skipped/skipped_names` 不变 | commands.rs、api.ts |
| 状态查询 | `list_tunnels -> Vec<TunnelInfo>` | 结构不变（`state` 内含 `Failed(Msg)`，随上表联动） | 无额外改动 |

**传输路径不变项（禁止清单的一部分）**：三个事件名（`tunnel://state-changed` / `tunnel://notice` / `tunnel://password-required`）、所有命令名、`PasswordRequiredPayload` 的非 prompt 字段、`App.tsx` 的 prevStateRef 跳变检测逻辑（只换 message 的渲染方式）。

### 2.3 前端 i18n 基建

**新增 `src/i18n.ts`**（唯一初始化点）：

```ts
import i18next, { type i18n as I18n } from "i18next";
import { initReactI18next } from "react-i18next";
import zh from "./locales/zh.json";
import en from "./locales/en.json";

export const LANG_STORAGE_KEY = "portunnel.language";
export type Lang = "zh" | "en";

// H3: zh* → zh，其余 → en；手动选择 > 系统 > 默认 zh（A1）。
export function resolveLanguage(): Lang {
  try {
    const saved = window.localStorage.getItem(LANG_STORAGE_KEY);
    if (saved === "zh" || saved === "en") return saved;
  } catch { /* storage unavailable → system detection */ }
  return navigator.language?.toLowerCase().startsWith("zh") ? "zh" : "en";
}

void i18next.use(initReactI18next).init({
  resources: { zh: { translation: zh }, en: { translation: en } },
  lng: resolveLanguage(),
  fallbackLng: "zh",                 // A4：key 缺失回退 zh，不显示裸 key
  interpolation: { escapeValue: false },
  react: { useSuspense: false },
  initImmediate: false,              // 静态资源同步 init，首帧即正确语言
});

/** 渲染一条后端消息；非渲染路径（事件回调等）也可安全调用（总是当前语言）。 */
export function renderMsg(m: LocalizedMessage): string {
  return i18next.t(`msg.${m.code}`, { ...(m.params ?? {}) });
}

export default i18next as I18n;
```

依赖：`i18next@^24`、`react-i18next@^15`（React 19 兼容线；精确版本由 npm lock 决定，不锁死 minor）。`tsconfig.json` 已开 `resolveJsonModule`，locales 直接 `import`。

**语言切换（`applyLanguage`，也在 `src/i18n.ts` 导出）**：

```ts
export async function applyLanguage(choice: "auto" | Lang): Promise<void> {
  try { window.localStorage.setItem(LANG_STORAGE_KEY, choice); } catch { /* ignore */ }
  await i18next.changeLanguage(choice === "auto" ? resolveLanguage() : choice);
  // A2：托盘与标题经重建命令同步（§2.5）。失败仅弹 warn banner，不影响切换。
  await invoke("set_window_title", { title: i18next.t("app.windowTitle") });
  await invoke("rebuild_tray", { labels: {
    show: i18next.t("tray.show"),
    reconnectAll: i18next.t("tray.reconnectAll"),
    quit: i18next.t("tray.quit"),
    tooltip: i18next.t("app.windowTitle"),
  } });
}
```

**t 的两条使用规则（过期闭包风险的对策，施工与评审都按此核对）**：

| 路径 | 用法 | 原因 |
|---|---|---|
| 组件渲染路径（JSX、render 期派生） | `const { t } = useTranslation()` | 语言切换触发订阅组件重渲染（A2 的 React 侧） |
| 非渲染路径（`useEffect` 内注册的事件监听器、IPC `.catch`、`tunnelEditorForm.ts` 等非组件模块） | `import i18n from "./i18n"` 后 `i18n.t(...)`，调用时求值 | 监听器/回调闭包不随语言切换重建，hook 的 `t` 快照会过期；实例调用永远当前语言 |

例外——**banner 的渲染定格**（C7）：`App.tsx` 的 `notify(level, message)` 收到的已是渲染后字符串，存入 state 后不再重翻。事件监听器里用 `i18n.t` 定格 = 「新消息用收到时的语言」，与 C7 一致。

**表单校验消息结构化**（`tunnelEditorForm.ts` 保持无 i18n 依赖）：`FormFieldError { field, message }` 改为 `{ field, code, params? }`（code 用 `editor.validate.*` key），UI 层 `ErrorHints` 渲染时 `t()`。与后端消息码同一模式：语言切换时已打开的编辑器随重渲染刷新校验文案。

### 2.4 语言设置入口（G5/D3）

**新增 `src/components/SettingsModal.tsx`**，复用 `TunnelEditor` 导出的 `Overlay`；`App.tsx` header 增加「⚙ 设置」按钮（`btnSecondary` 样式）打开。

- **语言区**（即时生效，无保存按钮）：三选一 segmented/radio——`跟随系统`（`auto`，默认）/ `简体中文`（`zh`）/ `English`（`en`）。当前值读 `localStorage[LANG_STORAGE_KEY]`（无记录 = auto）；onChange 直接 `applyLanguage(choice)`。
- **检查更新区（仅占位，N6）**：disabled 按钮「检查更新」+ 副文案「即将推出」（`t("settings.checkUpdate")` / `t("settings.comingSoon")`），无任何逻辑，为自动更新提案预留位置。
- localStorage key：`portunnel.language`，存 `"auto" | "zh" | "en"`；`auto` 时每次启动按 `resolveLanguage()` 现算（系统语言变化可被跟随）。读取/写入全部 try/catch，storage 不可用时退化为纯内存选择（当次会话生效）。

**启动时序**：`main.tsx` 同步 `init` 后 `createRoot(...).render(<App/>)`；`App.tsx` 挂载 `useEffect` 里立即 `applyLanguage(localStorage 原值)` 一次（幂等：写回同值 + `changeLanguage` 同值 no-op + 重建托盘/标题），把托盘与标题从后端兜底文案（§2.5）刷新为实际语言。

### 2.5 托盘重建与窗口标题（G4）

**后端（lib.rs + commands.rs）**：

1. `setup_tray` 改造：`TrayIconBuilder::new()` → `TrayIconBuilder::with_id("main")`；菜单构建抽成
   `fn build_tray_menu(app: &tauri::AppHandle, l: &TrayLabels) -> tauri::Result<Menu<Wry>>`
   （四个 `MenuItem::with_id`，**id 仍为 `"show"/"reconnect"/"quit"`**——事件匹配键是逻辑 id，与文案无关，`on_menu_event` 分发代码零改动）。`setup_tray` 用硬编码中文初始文案构建（现状文案），作为前端接管前的兜底。
2. 新命令（commands.rs，注册进 `lib.rs` 的 `generate_handler!`）：

```rust
#[derive(Serialize, Deserialize)]
#[serde(rename_all = "camelCase")]
pub struct TrayLabels { pub show: String, pub reconnect_all: String, pub quit: String, pub tooltip: String }

#[tauri::command]
pub async fn rebuild_tray(labels: TrayLabels, app: tauri::AppHandle) -> Result<(), Msg> {
    let tray = app.tray_by_id("main").ok_or(Msg::TrayMissing)?;
    let menu = build_tray_menu(&app, &labels).map_err(|e| Msg::TrayUpdateFailed { detail: e.to_string() })?;
    tray.set_menu(Some(menu)).map_err(|e| Msg::TrayUpdateFailed { detail: e.to_string() })?;
    tray.set_tooltip(labels.tooltip.as_str()).map_err(|e| Msg::TrayUpdateFailed { detail: e.to_string() })?;
    Ok(())
}

#[tauri::command]
pub async fn set_window_title(title: String, app: tauri::AppHandle) -> Result<(), Msg> {
    let win = app.get_webview_window("main").ok_or(Msg::MainWindowMissing)?;
    win.set_title(&title).map_err(|e| Msg::SetTitleFailed { detail: e.to_string() })
}
```

3. **线程模型**：command 在 Tauri 的 async runtime 线程执行；Tauri 2 的 `TrayIcon::set_menu/set_tooltip` 与 `WebviewWindow::set_title` 均为线程安全 API（内部 dispatch 主线程），无需手动 `run_on_main_thread`。**采用原地 `set_menu` 更新而非销毁重建 TrayIcon**（销毁重建有图标闪烁、事件重挂载与 Windows 托盘残留风险，见 §7 被否决方案 X4）。

**窗口标题双保险**：
- `tauri.conf.json` 的 `windows[0].title` 从 `"SSH 隧道管理器"` 改为 `"portunnel"`（与 productName 一致、语言中立）——启动瞬间任何语言下都不闪错误语言；前端接管后按当前语言 `set_window_title(t("app.windowTitle"))` 覆盖（需求基线 §6 已定此兜底关系）。
- 前端 `applyLanguage` 每次语言变化与启动时都调 `set_window_title`。

**失败收敛**：两个命令失败（托盘缺失/窗口缺失/平台调用失败）返回 `Msg`，前端 catch 后 `notify("warn", renderMsg(...))`——文案停留在上一语言，属可接受的降级，不阻断语言切换。

### 2.6 一致性校验（A4/A5 的自动作证）

零新依赖，两个 node 脚本 + 一条 npm 命令：

1. **`scripts/check-locales.mjs`**：递归扁平化 `src/locales/zh.json` 与 `en.json` 的 key 集合，diff 不等则打印缺失侧 key 列表并 `exit 1`。
2. **`scripts/check-msg-codes.mjs`**：从 `src-tauri/src/model.rs` 用正则提取 `pub enum Msg` 的变体名（形如行首 `VariantName {` / `VariantName,`），PascalCase→camelCase，要求与 `zh.json`/`en.json` 的 `msg.*` key 集合完全相等，不等则列出两侧差异并 `exit 1`。
3. `package.json` 增加：`"check:i18n": "node scripts/check-locales.mjs && node scripts/check-msg-codes.mjs"`。

**可执行命令**：`npm run check:i18n`（A4 验收命令）。三层一致性防护 = TS 判别联合（编译期）+ check:i18n（仓库期）+ `renderMsg` 对未知 code 走 i18next fallback（运行期，最终兜底）。

## 7. 被否决的备选设计

| # | 方案 | 否决理由 |
|---|---|---|
| X1 | 后端感知语言并直接产出译文（rust-i18n / 后端存 locales，前端拉取） | 需求基线 D2/C6 已否决且为红线：后端要维护语言状态（进程级全局或每消息传参）、三处入口（托盘/事件/命令）各自同步语言、切语言需广播或重启；且与「翻译只放前端」的 C6 冲突。码化方案下后端完全无语言概念，切语言零后端参与 |
| X2 | 半码化：只翻前端静态文案，后端错误保留中文硬编码（或英文） | 英文界面弹中文 banner（或反之），直接违反 A3 与 G3；后端文案是排障主路径，不码化则双语覆盖为假 |
| X3 | 中文原文作 i18n key（natural key，`t("加载隧道列表失败")`） | 改文案 = 改 key = 全调用点联动；含参数的模板（"已导出 {{n}} 条"）无法作为 key；zh/en 集合校验失去意义（zh 文件退化为恒等表）。稳定语义 key + msg-code 脚本校验在改文案场景下成本最低 |
| X4 | 语言切换时销毁并重建整个 TrayIcon（`app.remove_tray()` + 重新 build） | 图标闪烁；`on_tray_icon_event`/`on_menu_event` 需重新挂载，扩大回归面；Windows 上托盘图标销毁/重建有残留幽灵图标的历史问题。原地 `set_menu`+`set_tooltip` 只换菜单对象与文案，事件分发零改动 |
| X5 | i18next TypeScript key 类型生成器（i18next-typescript / type-fest JsonObject 声明）引入 t(key) 编译期校验 | 新增生成器依赖与「改 locales 必须重新生成类型」的构建步骤；本项目 key 规模 ~200，且后端消息已有 TS 判别联合 + `check:i18n` 脚本闭环。静态 UI key 的拼写错误由 fallback zh + S10 残留 grep 兜底，收益不抵工具链成本（加语言时再评估） |
