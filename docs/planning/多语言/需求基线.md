# 需求基线：多语言支持（i18n，中/英）

> 状态：**主控冻结（2026-11-21）**
> 主题 slug：`i18n`（worktree 分支 `pipeline/i18n-20261121-145315`，基线 commit `4fbb48d`）
> 关联代码：`src/`（全部组件）、`src-tauri/src/`（tunnel.rs、model.rs、lib.rs 等）、`tauri.conf.json`、`README.md`、`CLAUDE.md`

## 0. 主题与参数说明

/pipeline 参数为「多语言和多语言」，按「多语言」单一主题推进（重复为笔误，讨论收尾时已明确先实施 i18n；自动更新为独立提案 [[提案-自动更新]]，不在本 pipeline 范围）。

## 1. 目标

- **G1** 引入 react-i18next（i18next + react-i18next）作为前端 i18n 框架，翻译资源为 `src/locales/zh.json` 与 `src/locales/en.json`。
- **G2** 前端全部用户可见文案改为翻译 key 调用，完成中英文两份翻译。
- **G3** Rust 后端用户可见消息（错误 + 成功提示）改为「消息码 + 插值参数」结构化传输，由前端 locales 统一翻译；后端不感知用户语言。
- **G4** 托盘菜单与窗口标题随语言切换重建（Rust 提供重建能力，文案由前端传入）。
- **G5** 新增语言设置入口：默认跟随系统语言，可手动切换，选择持久化（localStorage），切换即时生效。入口预留「检查更新」位置但本次不实现该功能。
- **G6** README 双语化：`README.md` 改为英文（GitHub 门面），新建 `README.zh-CN.md` 中文版，两文件顶部互链；内容以中文为源。

## 2. 验收标准（可判定）

- **A1 语言默认与持久化**：应用首次启动（localStorage 无记录）时，系统语言为 `zh*` 显示中文、否则显示英文；用户手动选择语言后写入 localStorage，重启应用后仍生效。通过标准：代码实现该逻辑 + 评审核对检测/持久化/覆盖优先级（手动 > 系统 > 默认 zh）三段均在。
- **A2 切换即时生效**：切换语言后，已挂载的 React 组件文案立即更新（无需重启）；托盘菜单与窗口标题通过重建命令同步更新。通过标准：代码实现 + 评审核对语言变更路径同时覆盖 React 重渲染与托盘/标题重建调用。
- **A3 双语覆盖无残留**：英文模式下前端界面、后端错误/成功 banner、托盘菜单、窗口标题无中文残留；中文模式下无英文残留。通过标准：locales 两文件 key 集合相等校验通过 + 评审核对全部文案来源（组件、消息码、托盘、标题）均有双语条目。GUI 运行时人工走查不属自动验收，列为终态人工验收建议（见 §6）。
- **A4 回退与完整性**：i18next fallback 语言为 zh，key 缺失不显示裸 key；存在 zh/en key 集合一致性校验（测试或脚本）且当前全部通过。通过标准：校验命令真实跑通。
- **A5 后端消息结构化**：后端错误（约 31 处构造点）与成功提示均以消息码 + 参数结构经事件传输，前端 locales 覆盖全部消息码；`ConnectError::Fatal/Retriable` 分类逻辑、认证两阶段流程、重连状态机行为不变。通过标准：评审核对消息码枚举双侧（model.rs / types.ts）一致且全部有文案，`cargo test`（parser 单测）通过。
- **A6 README 双语**：`README.md` 为英文、`README.zh-CN.md` 为中文，两文件存在且顶部互链，章节结构一一对应。通过标准：三事实（英文内容、中文内容、互链存在）+ 章节对齐由评审核对。
- **A7 约定文档更新**：CLAUDE.md「UI 文案一律中文」条目改为 i18n 约定（文案进 locales，zh 为默认/回退语言；注释英文）。通过标准：diff 中可见该条目改写。
- **A8 构建与测试**：`npx tsc --noEmit` 通过；`npm run build` 通过；`cargo build` 通过且 `tunnel.rs` 无新增警告；`cargo test` 通过。通过标准：四条命令在本 worktree 真实跑通。

## 3. 非目标（不做什么）

- **N1** 不做多语言发布说明（Release 说明维持中文）。
- **N2** 不做日期/数字格式本地化。
- **N3** 不做 RTL 语言支持。
- **N4** 不翻译服务器发来的 `keyboard-interactive` 提示语（服务器原文如实显示）。
- **N5** 不做营销级翻译润色，按工具型应用简洁技术用语标准。
- **N6** 不实现「检查更新」功能（自动更新为独立提案），设置入口仅预留位置；不引入 CI 强制 README 同步校验。

## 4. 约束与禁止项

- **C1** `src-tauri/src/model.rs` 与 `src/types.ts` 字段/枚举手动保持一致（消息码枚举双侧同步）。
- **C2** 代码注释英文、UI 字符串一律经 locales（新增约定，替代原「UI 文案一律中文」，写入 CLAUDE.md）。
- **C3** 不改变任何业务逻辑：认证两阶段流程、`Fatal/Retriable` 错误分类、重连退避、`Stop/Reconnect` 竞速、公钥上传流程均不动；本需求只改「消息的构造与展示形式」。
- **C4** 钥匙串命名约定（`user@host:port`、`__targetuser__@host:port` 前缀）不动。
- **C5** 不修 cargo clippy 历史遗留风格警告（manager.rs/parser.rs 已知项）；`tunnel.rs` 保持零警告。
- **C6** 翻译文件只放前端（`src/locales/`），后端不引入 i18n 依赖。
- **C7** 历史已显示的 banner 不随语言切换重翻（保留原语言），新消息用新语言——接受此行为。

## 5. 已定决策（来自讨论确认，设计不得推翻）

## 6. 边界与异常场景结论

- 服务器 `keyboard-interactive` 提示语：原文显示（N4）。
- 窗口标题：tauri.conf.json 静态 title 仅作启动瞬间兜底，前端初始化后按当前语言 setTitle 覆盖。
- 语言切换时已打开的弹窗（如密码弹窗）：随 React 重渲染即时切换文案；正在输入的内容不丢失（H1）。
- 自动检查更新等不存在功能不涉及。
- GUI 运行时全界面走查属人工验收，不进自动验证（A3 已定义自动验收口径）。

## 7. 假设（主控自行决断，标注供终态对照）

- **H1** 密码弹窗等已打开弹窗在语言切换时即时重渲染文案，输入态不受影响（React 常规行为，实现后由评审核对无状态丢失隐患）。
- **H2** `/pipeline` 参数「多语言和多语言」为笔误，主题为「多语言」单一主题（见 §0）。
- **H3** 语言代码归并规则：`navigator.language` 以 `zh` 开头归为 zh，其余归为 en（两语言阶段的最简归并，后续加语言时扩展）。

## 8. 假设被推翻时的波及

- H1 若不成立（存在输入态丢失或渲染异常），影响面为 PasswordModal/TunnelEditor 的语言切换时机，处理方式为记录裁决并让实现者改为「切换后关闭重开弹窗」级别的显式处理。
- H2 若用户本意含「自动更新」主题，本次只交付「多语言」，自动更新另行 /pipeline（互不阻塞）。
- H3 归并规则变化（如需支持 `zh-TW` 独立语言）只影响语言检测函数，不影响整体结构。
