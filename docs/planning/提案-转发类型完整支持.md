# 提案：转发类型完整支持（-D 动态 / -R 远端 / -J 多跳）

> 状态：方案主干与第一期（-D）细节已经用户确认（2026-11-19 讨论收敛）；第二、三期为路线级占位，实施前需补充细节章节再动手。
> 关联：代码模块 `src-tauri/src/{model,parser,tunnel,manager,probe,store}.rs`、`src/types.ts`、`src/components/{TunnelEditor,TunnelList}.tsx`；竞品背景见会话结论（Core Tunnel / Termius / Termalin 均三种转发全支持，`-D` 为最高频缺口）。
> 读者：后续实施者（含 subagent）。

## 0. 一句话结论

分三期把转发能力从"仅单跳 `-L`"补齐为 "`-L` + `-D` + `-R` + `-J`"：先加规则类型字段（存量配置零迁移），`-D` 复用现有直连通道路径 + 最小 SOCKS5 服务端；`-R` 引入服务器推送通道的回调架构；`-J` 沿用代码库已验证的嵌套通道模式并重构跳板链模型。

## 1. 问题

- 竞品对比结论：转发类型只覆盖 `-L` 是本应用与同类产品对位时最明显的功能缺口，其中 `-D`（把跳板机当 SOCKS 代理访问整个内网）是这类工具的高频诉求。
- 用户决策（2026-11-19）：劣势 1（转发类型）完整实现；劣势 2（内置终端）**明确不做**——市面已有大量终端，不重复造；劣势 3（移动端）、4（成熟度）暂不考虑。

## 2. 现状核对（已查证事实）

| 事实 | 对本需求的意义 |
|---|---|
| `TunnelConfig.forwards: Vec<ForwardSpec>`，`ForwardSpec { local_port, remote_host, remote_port }` | 多条规则早已支持（一条命令多个 `-L` 可解析）；真正的差距是规则**类型**单一 |
| `parser.rs` 已把 `-D`/`-R`/`-J` 列入"带参数旗标"清单静默吞掉 | 解析框架已在，加分支即可 |
| `tunnel.rs` 的 `setup_second_layer`/`open_target_session` 已实现 direct-tcpip channel → `into_stream()` → `connect_stream` 的嵌套 SSH 连接 | **`-J` 多跳的底层机制在本代码库已有可运行先例**，可行性疑问已排除 |
| 断线检测靠 `SshClientHandler` 的 Drop 信号；SSH Config 按连接独立构造 | 多跳时"任何一跳断都触发重连"需逐跳接力信号链；每跳 keepalive 需各自配置 |
| `probe.rs` 探测/杀端口只懂本地端口 | `-R` 的端口在服务器上，探测逻辑须按类型跳过 |
| `TunnelEditor` 是"粘贴 ssh 命令 → 解析 → 预览"驱动，**无逐行规则编辑器** | `-D` 的 UI 增量仅为预览/摘要文案按类型渲染，工作量小 |
| `probe_port` 的 heuristic（连得上 + 不立即断开 = 健康）对 SOCKS 端口天然成立 | 启动时的外部隧道探测（`detect_existing`/`mark_external`）对 `-D` 端口无需改算法 |
| 钥匙串按 `user@host:port` 命名（`store.rs`） | 多跳各跳天然不冲突 |
| russh 0.44 在用；`channel_open_direct_tcpip` / `connect_stream` / `into_stream` 已使用 | `-R` 所需的 tcpip-forward 全球请求与 forwarded-tcpip 回调 API 存在，具体签名实施时核对 |

## 3. 方案

### 3.0 总体路线（已定：分三期交付）

| 期 | 版本 | 内容 | 定位 |
|---|---|---|---|
| 一 | v1.3 | `-D` SOCKS 动态转发 | 90% 复用现有路径，价值最高，先交付 |
| 二 | v1.4 | `-R` 远端转发 | 唯一动客户端回调架构的期，独立成期便于回归认证/断线逻辑 |
| 三 | v1.5 | `-J` 多跳 | 牵动认证全链路与模型重构，最后做 |

理由：`tunnel.rs` 连接状态机是本项目历史真实 bug 最密集区域，三种语义混在一个版本回归面过大、难定位。分三期 = 三轮完整发布流程（含打 tag，见项目 CLAUDE.md 发布规范）。

### 3.1 第一期（v1.3）：`-D` 动态转发

**模型与序列化（决策⑦）**

- `ForwardSpec` 保持平铺三字段，新增 `kind: ForwardKind` 字段，`#[serde(default)]` 默认 `Local`。`ForwardKind ∈ { Local, Dynamic }`。
- `Dynamic` 规则的 `remote_host` 存空串、`remote_port` 存 0（占位），读取按 kind 解释；对"这条规则的目标地址"等访问统一走辅助方法（如 `target()` 对 Dynamic 返回 None），避免占位值外泄到业务逻辑。

三向兼容（选择此格式的理由）：

| 场景 | 结果 |
|---|---|
| 旧配置升级到新版 | 无损（kind 缺省读为 Local） |
| 新版导入旧版导出的备份 | 无损（同上） |
| 新版配置回滚到旧版 | 不崩（旧版忽略未知 kind 字段，Dynamic 规则显示为一条目标为空的怪规则，列表完整） |

备选（已否决）：serde 带标签枚举格式更"标准"，但旧版读新格式会整表解析失败、旧备份导入需额外适配，兼容面反而差。

**解析器**

- `-D 端口` / `-D端口` / 与 `-L` 混用（一条隧道混合规则，与 ssh 一行多 flag 语义对齐）。
- `-D [bind:]port` 的可选绑定前缀**忽略**（与现有 `-L` 四段式解析丢弃 bind 前缀行为一致）；全局 `-g`（`bind_all`）对 SOCKS 监听同样生效。
- 解析结果为空规则集时报错行为与现状一致。

**SOCKS5 最小服务端（新独立文件，不动 `tunnel.rs` 整体结构）**

- 仅 CONNECT、仅免认证（method 0x00；客户端只支持需认证方法时回 0xFF 拒绝）。
- 拒绝 BIND / UDP ASSOCIATE（回复命令不支持）。
- 地址类型支持 IPv4 / 域名 / IPv6（ATYP 1/3/4）。
- **域名目标原样传给 direct-tcpip，由跳板机侧解析**——与 `-L` 写内网域名的行为一致，内网域名靠此才通。
- 通道打开失败时映射为对应 SOCKS 错误码（connection refused / host unreachable / general failure），客户端拿到可读错误而非干等。
- 每连接独立开通道，与 `-L` 并发模式一致；**监听任务在断开竞速区间之外生成、清理时统一中止**（遵守项目已知任务泄漏教训）。

**其余触点**

- `:22` 二级登录预检：`Dynamic` 规则跳过（无固定目标）。
- `probe_forwards` 遍历规则改用取本地端口的辅助方法；算法不变。
- `types.ts` 同步 `kind` 字段；`TunnelEditor` 预览行、`TunnelList` 摘要凡展示转发信息处按类型渲染（如 `本地 :1080 → SOCKS 代理`）；`TunnelList` 具体渲染点实施时核对。

### 3.2 第二期（v1.4）：`-R` 远端转发（路线级占位，实施前细化）

- 方向反转：向服务器发 tcpip-forward 全球请求，由服务器监听、经 forwarded-tcpip 通道把连接推给本应用，再接到本地目标。
- `SshClientHandler` 目前是无状态壳（仅 disconnect_tx），需扩展一条"把推送来的连接交给隧道任务"的通道；不得破坏 Drop 断线信号语义。
- 规则允许可选的服务器侧绑定地址（与 ssh `-R [bind:]port:target` 语法对齐），默认只绑服务器回环（安全默认，与主流服务器 GatewayPorts 配置一致）。
- 重连成功后须重新向服务器申请监听。
- 远端端口被服务器拒绝时给出可读错误（"远端端口被占用"），且**不得无限重连**——错误分类的新分支（Fatal 倾向）。
- `probe`/杀端口逻辑按类型跳过远端端口（那是服务器上的进程，不能也不该 kill）。
- 状态语义：绿灯 = 服务器已开始监听远端端口。
- russh 0.44 的 tcpip-forward / forwarded-tcpip 客户端回调 API 签名实施时核对。
- 可选小项（倾向支持）：`-R 0:target` 动态分配端口，申请成功后把实际端口回填 UI（tcpip-forward 应答携带）。

### 3.3 第三期（v1.5）：`-J` 多跳（路线级占位，实施前细化）

- 连接方式：沿用 `open_target_session` 已验证的嵌套通道模式（"通道当网线"逐跳内连）；**不用**本地垫脚临时端口（占本地端口、与探测/竞速取消纠缠）。
- 认证：**每一跳完整走两阶段认证**（独立连接公钥先行、密码/KBI 另起连接）——低 MaxAuthTries 服务器不会因是中间跳而豁免；密码弹窗 layer 字段从 "jump"|"target" 扩展为带跳数与主机名的标注（"第 2 跳 hostX"）。
- 模型：跳板从 `jump_user/jump_host/jump_port` 三平铺字段重构为 `hops: Vec<Hop>`，**一次性存量数据迁移**（store 层，含测试）。选在此时机因为：唯一需要它的期；当前用户基数小，迁移窗口成本最低。
- 断线信号逐跳接力：任一跳断开均触发退避重连，漏一跳即"绿灯但不通"。
- 每跳 keepalive 独立配置（SSH Config 按连接构造的现状已支持）。
- `:22` 预检只看最终转发目标（中间跳本身即 SSH 登录，无需预检）。
- 解析：`-J user@h1:port,user@h2`（逗号分隔多跳）完整语法。
- 钥匙串 `user@host:port` 命名天然支持多跳，无需改。

## 4. 边界与不变式（验收标准）

**第一期（v1.3）验收**

- 本机以 SOCKS5 代理方式经跳板访问仅内网可达的服务成功，**含内网域名目标**（验证跳板机侧解析）。
- 断线退避重连后代理端口恢复可用。
- 存量配置升级后原隧道行为不变。
- 粘贴 `ssh -L 10008:host:3306 -D 1080 user@jump` 一次建出混合规则隧道，两种转发同时工作。
- 硬性回归：现有单跳 `-L` 全流程零回归（两阶段认证、密码错误红灯、连接中可打断、`:22` 预检、公钥上传）。

**通用不变式（各期均适用）**

- 任何新增监听/连接处理任务不进入断开竞速区间；清理时统一中止，无任务泄漏。
- 认证失败类错误 = 红灯不重连；网络类 = 退避重连。新增错误路径必须归对类。
- 密码类弹窗的取消 = 断开连接（不是仅关 UI）。
- `tunnel.rs` 保持零警告；改完前端跑 `npx tsc --noEmit`，改完 Rust 跑 `cargo build` + `cargo test`。
- UI 文案中文、代码注释英文。

**二、三期验收（路线级，实施前细化）**

- `-R`：从服务器侧访问远端端口能打到本地服务；重连后服务器侧监听自动恢复；远端端口冲突给可读错误且不无限重连。
- `-J`：两跳隧道转发可用；任一跳认证失败的红灯文案能指明是哪一跳；中间跳断开触发退避重连；粘贴含 `-J` 的命令解析正确。

## 5. 决策项与取舍（全部已定）

| # | 决策 | 结论与理由摘要 |
|---|---|---|
| ① | 交付顺序 | 分三期。`-D` 复用最多价值最高；`-R` 动回调架构独立回归；`-J` 最重最后。备选一把梭因状态机回归面过大被否决。 |
| ② | 数据模型节奏 | 规则先加类型（存量零迁移），跳板链重构推迟到 `-J` 期。避免前两期背上无关的迁移风险。 |
| ③ | SOCKS5 实现 | 手写最小实现（仅 CONNECT、免认证），不引第三方库。需求面窄、少依赖少审计面。 |
| ④ | `-R` 服务器侧绑定 | 规则允许可选绑定地址，默认回环（安全默认，对齐主流服务器 GatewayPorts 行为）。 |
| ⑤ | 多跳认证 | 每跳完整两阶段认证；弹窗标注第几跳 + 主机名；`:22` 预检只看最终目标。 |
| ⑥ | 多跳连接方式 | 嵌套通道模式（代码库已验证）；否决本地垫脚端口。 |
| ⑦ | 序列化兼容 | 平铺三字段 + `kind`（serde default）+ Dynamic 占位空目标。三向兼容最全、无需自定义反序列化；代价是占位字段，用辅助方法消化。 |

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| 新增监听/推送任务进入断开竞速区间 → 取消时任务泄漏 | 沿用现有"竞速区间外 spawn、cleanup 统一 abort"模式，评审时专项检查 |
| 远端端口冲突被误归为可重试错误 → 无限重连 | 第二期错误分类专项设计（倾向 Fatal + 可读文案） |
| 多跳断线信号漏接 → 绿灯但不通 | 第三期信号链逐跳接力设计 + 断中间跳的验收用例 |
| 回滚行为：新版配置回滚到旧版显示怪规则 | 接受（见决策⑦兼容表）；应用有导出/导入可兜底 |
| russh 0.44 API（tcpip-forward / forwarded-tcpip 回调）与预期不符 | 第二期实施前先写 API 探针小样验证，再铺开 |
| SOCKS5 握手细节 bug（IPv6/域名解析边界） | 握手解析做纯函数单测；验收含域名目标用例 |

## 7. 不做什么（非目标）

- **内置终端**：用户明确不做，市面已有大量终端。
- 移动端。
- `-W` stdio 转发、agent 转发。
- known_hosts 严格校验（维持现状 TOFU）。
- 逐行转发规则编辑器：保持"粘贴 ssh 命令 → 解析 → 预览"驱动的产品形态，模型可表达即可。
